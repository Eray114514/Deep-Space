# T：星球地表重做（地形、地表材质、植被）

立项于 2026-11-16，是地形、地表材质和植被的唯一执行文档。路线图和任务表只放一句状态，并链接到这里。范围、方案和验收有变化时改本文；某一项验收后，从“待办”里删掉，把证据链接记到“完成记录”。

本批次替换原路线图 C 批次里的植被与材质条目（C-01～C-08），也替换“A 已验收”里关于地形观感的部分。A 验收的连续 LOD、接缝、近水、海洋和碰撞仍然有效，继续作为底座。

## 为什么要重做

用户实机反馈，2026-11-16 用 GPU Chrome 截图复核（1600×900，`?nohero=1&scene=orbit|lowflight|walk`）：

| 现象 | 实际原因（代码事实） |
|---|---|
| 从轨道看像低多边形，假 | 地表颜色由 `planet.colorAt` 在网格顶点上算，光照用顶点法线（`quadtree.js`，每块 32～64 格）。从轨道看一个顶点覆盖数公里，只剩色块和折面，没有逐像素的地貌信息 |
| 地貌单调，没有可读的山河 | 高度是分形、山脊、峡谷、陨石坑等解析噪声的叠加（`terrain-height-field.js`），没有侵蚀、河网、冲积扇和沉积。颜色主要按海拔分层，加湿度和斑块噪声 |
| 低飞时地面是一整块平板 | 同上；另外 1200 km 母星的起伏只有几公里，中景缺少细节层级，地表纹理只在近处生效 |
| 植被完全不可用 | `flora.js` 的设计就是“low-poly flat-shaded”：5 棱柱树干、二十面体树冠、逐顶点纯色。摆放接近均匀撒点，远处排成行。`farflora.js` 的远景代理也是同一种风格 |
| 地面材质贫乏 | 只有两套 1k 贴图（Poly Haven 的 `sparse_grass`、`rock_ground`），按草/岩二选一混合 |

结论：植被全部重做；地形保留 LOD、接缝和碰撞底座，重做地表着色，大改生成器。

## 目标

- **画面标尺**：写实，以 Star Citizen、Starfield 的地表为参照。外星星球在写实基础上改变形态、配色和生态，不靠低多边形做风格。
- **轨道**：读得出山脉走向、河谷、海岸、森林和草原的边界、荒漠、雪线，云影下的地表也有层次。
- **低飞**（300 m～5 km）：地形有起伏和细节层级，森林是一片片的树冠，不是色块。
- **地面**：草、灌木、树、岩石、地被组成可信的生态，材质近看不重复、不拉伸。
- **连续性**：从轨道降到地面全程没有明显的跳变、突然出现或闪烁。
- **性能**：默认画质下，RTX 笔记本 2K 从轨道到低飞不低于 60 FPS、地面步行不低于 60 FPS（以当前 `perftest` 路线为准）。冷启动不比现在多出 2 s 以上。

## 不变的约束

- WebGL 2 / GLSL，按 AGENTS.md 的渲染基准。
- 确定性：所有生成结果从星球种子导出，不用 `Math.random()`。新的生成步骤用新的 RNG 命名空间。
- **碰撞以 CPU 端的高度为准**。`TerrainHeightField` 继续作为能放进 worker 的唯一高度来源，近水 worker 和降落、步行的物理都依赖它。GPU 只加不影响碰撞的视觉细节（法线、颜色、材质权重）。
- 宇宙锁：按 AGENTS.md 的重构期约定暂不处理。地貌会变，重构结束后在 W 阶段统一重筛。
- 保护 A 的成果：LOD 形变和接缝统计（`lodStats`）、近水精度和海面交接不能退化。

## 总体方案

### 1. 地表着色：逐块烘焙高精度表面图（先做，解决“从太空看像低多边形”）

- 每个地形块（四叉树节点）建好网格后，在 GPU 上为它烘焙一组表面图：法线、反照率和材质权重。分辨率是该块顶点网格的 4～8 倍（远处块 128²，近处块 256²），四周各留 1 个纹素的重叠，避免缝。
- 烘焙着色器是高度函数的 GLSL 版本，只负责网格分辨率以上的细节频段，所以它和 CPU 高度的细微差别只影响光照，不影响碰撞。坐标用块的局部原点加小量偏移，沿用 `SurfaceViewFrame` 已经验证过的精度做法。
- 表面图放在纹理数组池里（预计 256 层 × 2～3 张，约 50 MB），按块的可见性租借和回收。烘焙走现有的 GPU 准备队列，每帧限额，与 `flushChunkQueue` 的预算协同。
- 地形材质从顶点颜色和顶点法线改成读表面图。顶点颜色只作为表面图到达前的回退。
- 地形材质从 `shaders-webgl.js` 拆到 `src/terrain/terrain-material.js`。原来的云影（`uCloudTex`）、日食、雪、近地细节等逻辑原样迁移，并给云线 2 留一个明确的云影接收接口。

### 2. 地貌生成器 v2：气候、侵蚀与河网

- **星球级宏观图**：星球加载时，在 worker 里生成一张立方体球面网格（每面 512²）：
  - 大陆和板块，造山带沿板块边缘分布；
  - 一次简化的水力侵蚀与沉积模拟，生成河谷、冲积平原、山前冲积扇和河网；
  - 气候场：纬度和恒星方向决定温度，海陆分布、盛行风和雨影决定湿度。
- 计算全部用 JS 双精度，结果在所有机器上逐位一致，可以直接给碰撞用。预算是 worker 内不超过 1.5 s。宏观图到达之前用解析版本渲染，到达后在下一次块重建时淡入，不阻塞启动。
- **细节层**：宏观图双三次采样，叠加带侵蚀效果的解析噪声：利用导数让陡坡出沟、谷底变平（思路参考 Inigo Quilez 的导数噪声文章，代码不能拷贝，只借鉴原理）。保留现有的陨石坑、沙丘、台地等地貌类型，并按气候分区出现。
- **生物群系**：由温度、湿度、海拔、坡度和离水距离决定，取代按海拔分层的配色。群系同时驱动地表材质、植被生态和轨道颜色，三者用同一套数据，所以从轨道看到的森林区就是地面真有树林的地方。
- 雪线由气温、坡向、受光和降水决定，南北半球和不同恒星方向都成立（原 C-07）。
- `planet.js` 的 `colorAt` 和 `biomeAt` 改为读宏观图和群系数据，散布系统用同一份数据。
- 海平面以下的海床、浅滩和海岸不受影响。海岸线位置变了以后，近水海岸的回归要复测（AR-02）。

### 3. 近地材质

- 用纹理数组存 8～12 套 PBR 材质：草地、林地落叶层、泥土、砾石、裸岩、崖壁、沙、湿沙/泥、雪、冰、火山岩。写实的类型用 CC0 照片扫描素材（Poly Haven、ambientCG），转成 KTX2 放进 `assets/surfaces/`，在 `SOURCES.md` 登记来源。外星和特殊地表用程序烘焙的材质组，沿用 Saltline 材质库的 GPU 烘焙框架。
- 混合方式：
  - 按群系权重和高度图混合，石缝里才有土，草从土里长出来；
  - 陡坡用三向投影，避免拉伸；
  - 用随机六边形平铺去掉重复感；
  - 远近两档频率衔接，再叠加宏观色斑。
- 雨天的地面变湿和雨点涟漪（原 L-3）在这一步接入：搬 Saltline 地面模块的着色器，雨量取天气系统的值，不改变高度。

### 4. 植被全部重做

- **树**：以 ez-tree 为生成器（MIT，参考目录 `../建议参考的优质项目/地面风景参考/ez-tree-main`，自带橡树、白蜡、杨树、松树和灌木预设）。星球加载时按种子生成该星球的 4～8 个物种：类地星球从预设派生，外星星球改分枝规律、叶形和配色。分级如下：
  - LOD0：完整网格加透明叶片，带树皮和叶片贴图；
  - LOD1：减少枝级和叶片；
  - LOD2：交叉面片；
  - LOD3：运行时烘焙的八面体视角替身。
  - 切换用抖动淡入淡出，同一棵树在各级的轮廓、颜色和风摆相位保持一致。
- **草**：GPU 实例化的草丛，包含叶片弯曲、簇团密度场、颜色变化和逐簇不同相位的风；中距离用草片，远处交给地表颜色。恶劣环境只有稀疏的杂草。
- **灌木、地被、花、蕨类**：用 ez-tree 的灌木预设和少量程序几何，按群系配比。
- **岩石**：程序生成高面数岩体（带层理、裂隙、凹腔），用岩石材质三向投影；大块崖壁和巨石也按群系分布。
- **外星植物**：保留 `flora.js` 的物种语法思路（球茎、伞盖、触手、发光荚），几何换成平滑高面数网格，加半透明叶片和自发光材质，不再用低多边形平面着色。
- **摆放**：按群系和生态规则：林地成团，林缘有过渡带，受坡度、湿度和离水距离控制；用分块泊松盘采样加密度噪声，不再均匀撒点。
- **无缝出现（硬要求，2026-11-16 用户提出）**：植被绝对不能突然出现。每一级都用连续的过渡：远处先由地表颜色和树冠色表示，再由替身逐株淡入（按屏幕像素大小和抖动遮罩，从 0 像素长大，不是到距离就整片出现），再换成网格。加载按需进行，在看得见之前就把分块准备好；准备不及时宁可晚一点淡入，不能弹出。草的密度同样按距离连续变化。
- **降落时的植被破坏（2026-11-16 用户提出）**：飞船降落不能和树穿模。引擎下洗气流把落点附近的草压倒、灌木吹弯，落点内的树被吹倒或折断并留在地上；飞船离开后痕迹保留一段时间。不做砍树之类的采集玩法。实现上每株植被有一个可被外力驱动的倒伏状态，由飞船位置、高度和推力决定，并给碰撞留出净空。
- ez-tree 是起点而不是约束（用户授权）：如果实测发现自己写生成器效果更好，或 ez-tree 有问题，主控直接换方案。
- 新代码放在 `src/vegetation/`，完成后删除 `flora.js`、`farflora.js` 和 `scatter.js` 里的旧低多边形物种。分块流式散布的框架如果合适就搬过去复用。

### 5. 远近一致

- 森林和草地在地表表面图里提前体现：树冠颜色、粗糙度和法线粗糙化，让轨道上的绿色区域往下飞时逐渐变成一片树林。
- 远景树木的替身密度和地表的树冠色互相淡入，在同一高度区间交接。
- 风场统一：草、树和云用同一天气风（`setWeatherWind`），对应原 B6-06。

## 参考与素材

- ez-tree（MIT）：`../建议参考的优质项目/地面风景参考/ez-tree-main`。接入时在 `assets/` 或 `vendor/` 写明来源、版本和许可；它附带的贴图许可要单独核实。
- Inigo Quilez 的地形文章（导数噪声、侵蚀外观）：只借鉴原理，参考目录里的着色器代码禁止使用。
- 照片扫描材质：Poly Haven、ambientCG（CC0）。
- Saltline 材质库（`src/saltline/materials.js`）：48 种材质全是人造物（混凝土、油漆、钢、锈、木、塑料、布、玻璃等），**没有草、土、岩、沙、雪这类自然地表**，不能直接当地形材质。可复用的有三样：GPU 程序烘焙框架（用来烘焙外星地表和岩石材质组）、共用着色器补丁里的三向投影、宏观色斑和雨湿逻辑（地表和岩石的雨湿可以照搬）、现成材质本身（给 E 批次的据点、道具和人造物用）。

## 风险

- **GLSL 与 CPU 噪声的差异**：只影响法线和颜色，不影响碰撞。验收看块边的光照接缝。
- **启动时间**：宏观图在 worker 里算并可以缓存。表面图和树的替身都按帧限额烘焙，冷启动预算写进 T6。
- **显存**：表面图纹理池、材质数组和植被替身都有上限，超出时降低远处块的分辨率，不能丢掉近处细节。
- **地貌改变**：现有截图、海岸测试夹具和重筛候选会失效。测试只更新期望值，不能为了变绿而改测试的含义。

### T0 工具与 T2a 生成器 v2（2026-11-16）

- **工具**：`node tools/surface-shots.js` 用硬件 GPU 的 Chrome 在同一地点拍 9 个固定机位（整球、300 km、100 km、30 km、8 km、2 km、400 m、地面两个方向），默认晴天、固定下午光照。`node tools/terrain-profile.js` 打印陆地高程分布、各基线的坡度和每次采样耗时。注意 `vclouds=0` 会换回旧的不透明云壳，不能用来"关云"。
- **实测的旧问题**：3 m、30 m、300 m 三个基线的坡度完全一样（16.6°），说明 1 km 以下没有任何地形内容；陆地中位海拔 1.6 km、全球到处一样陡，没有平原和山脉的对比；低地被 12% 高程带的"谷雾"整片罩住，从高空看一片灰白。
- **生成器 v2**（`terrain-height-field.js` 的 `height()`，参数在 `planet.js` 的 `:terrain-v2` RNG 命名空间）：
  - 地貌按物理波长定义，再用星球半径换算，小卫星不再是缩小版大陆；
  - 大陆轮廓沿用原来的场，海岸线布局不变，另加 9 个倍频把海岸细化成海湾、岬角和小岛；
  - 陆地高程压低（中位约 190 m），海盆深度不变；
  - 山脉是带坡度阻尼的脊状分形，只出现在造山带里，脊线做了域扭曲；
  - 丘陵、地表粗糙度（120～420 m）和脚下的微起伏（约 11 m 以下）逐级叠加；
  - 河谷下切限制在近海低地。
  - 噪声新增解析梯度版本 `noiseD`（与数值差分误差 5e-9），每次采样从约 5.3 µs 降到约 2.9 µs。
- **配色**（`shaders-webgl.js` 地形片元）：海拔到调色板加了曲线（`landT`，CPU 和着色器共用）；逐像素的气候斑块（干草原、草地、林地、苔原）；30 m 到 3 km 的多尺度地表色斑；雪线用噪声打碎并避开陡坡；岩石从 20° 坡开始露出（原来要 39°）；谷雾高程带从 12% 改为 1.5%。
- **证据**：`test-results/surface-shots/baseline-noclouds`（旧）对比 `test-results/surface-shots/v2-d`（新）。v2 的数据：陆地 p50=190 m、p90=1046 m、p99=2536 m；坡度 3 m 基线 13.9°、3 km 基线 5.0°、30 km 基线 2.3°。
- **验收**：`npm test` 除宇宙锁外全部通过（锁按重构期约定不处理，地貌改变是有意的）；`test:terrain`、`terrainheightfieldtest`、`test:smoke` 通过。`tools/terrain-height-oracle.js` 里冻结的 v1 高度函数已删除，测试改为用现行 `height()` 对照独立的陨石坑路径。未交 Hydrogen 验收；画面待用户实机确认。
- **已知不足**：低空和地面仍然是平坦草原加低多边形树（植被和近地材质还没动）；母星以外的星球类型只跑了 `test:terrain`，没有逐个看图。
