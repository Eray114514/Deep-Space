# 正式宇宙选种记录

发行版中银河系的正式种子是 `MILKY-038`。玩家不负责生成或重构银河；种子是开发期内容筛选工具。

## 筛选方法

`tools/curate-worlds.js` 使用按银河命名空间隔离的固定候选流（当前为 `DEEP-SPACE-CURATION-V1:milky-way`），对 1,024 个可复现候选进行第一轮静态筛选。评分覆盖出生星系天体类型、前四颗行星差异、可登陆环境、双星、巨行星、卫星数量，以及邻近 18 个星系的类型覆盖。静态得分只负责淘汰，不直接决定胜者。

第二轮使用 `tools/capture-world-candidates.js` 在相同镜头和渲染条件下检查出生轨道、各类主行星、低空地形、落地点与飞船回看。最终候选为：

- `SORO-559`：天体丰富，但出生地表较平，第一印象偏弱。
- `IOKAHE-742`：出生群岛山地突出，但巨行星重复度高，B 型伴星导致部分轨道视图过曝。
- `NADALA-118`：山海落地点优秀，但主系统环境覆盖略少。
- `MILKY-038`：双星、近月、宜居海岸、毒性世界、气态与冰巨星，以及丰富卫星形成最完整的首个星系节奏。

因此选定 `MILKY-038`。更改正式种子必须重新运行静态筛选、同镜头视觉比较和完整浏览器游玩，不能从随机结果中直接挑选。

## 银河与微调层

当前发行内容是一座银河：`milky-way`（银河系）。它包含许多恒星系；未来新增银河时，应在 `src/world-config.js` 注册新的银河 ID 与独立种子，而不是复用同一坐标空间。

正式种子仍然保持程序化生成的基础结果。少量策划微调按稳定路径 `银河 ID / 恒星系 ID / 天体 ID` 保存，目前支持海平面米制偏移与云量覆盖。`MILKY-038` 出生恒星系 `0,0,0` 的 `planet-0` 使用 `seaLevelOffset: -420`，用于增加可见大陆和海岸，不修改其他种子或天体。

黑洞不进入恒星格点概率，也不替换任何既有星系。银河配置显式注册唯一目的地 `black-hole:sagittarius-a`（显示名「人马座 A\*」，系统名「银河中心引力观测区」）；其中央黑洞和三颗俘获恒星使用独立命名空间 `compact-objects:v1`。因此调整黑洞外观、质量或轨道时不需要重新筛选 `MILKY-038`，只有主动升级普通恒星/行星生成器时才需要重跑上述选种流程。

## 正式宇宙锁

`worlds/milky-way.lock.json` 是当前正式宇宙的可读快照和兼容性锁。它保存出生星系完整天体摘要、黑洞目的地、最近 18 个星系、64 个邻近星系的总体分布，以及出生星球的地形高度、自然/微调海平面、云量和星环哨兵值。Agent 不必运行游戏就能先从该文件了解 `MILKY-038` 的大致内容，代码测试也能发现生成结果是否被意外改写。

锁文件不是完整宇宙存档。银河目录固定为 1,024 个恒星系，地形和纹理仍按需生成；把它们全部固化会制造巨型文件，并让扩展和多人同步更困难。运行时真相仍然是 `src/world-config.js` 加 `src/galaxy-layout.js` 与各版本化生成器，未来存档只需保存正式宇宙版本、稳定天体 ID 与玩家状态。

修改生成器后运行：

```powershell
npm test
```

如果宇宙锁失败，先判断漂移是否是预期行为。意外漂移应修复 RNG 调用顺序、命名空间或算法兼容性；只有明确接受重写宇宙，并重新完成静态筛选、固定镜头对比、浏览器游玩和存档/联机迁移评估后，才运行：

```powershell
npm run world:lock
```

禁止只为让测试通过而刷新锁文件。纯渲染外观改动如果不触及生成数据，应保持指纹不变；新机制应优先使用新的独立 RNG 命名空间，避免消耗旧随机流。
