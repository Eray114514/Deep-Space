# 发布宇宙与重筛流程

更新：2026-09-20。**全量重构期间不处理宇宙锁，不运行重筛或刷新锁来消除测试失败。** 本文描述内容身份与重构完成后的发布流程；何时重筛由用户决定。

## 当前内容身份

`milky-way` 使用种子 `MILKY-038`，普通目录固定 **1,024 个可达恒星系**。这是星系数量，不是候选种子数量。`src/world-config.js` 保存身份与按“银河 / 星系 / 天体 ID”的策划微调；`src/galaxy-layout.js` 的 `buildGalaxyCatalog()` 生成目录，行星表面仍按需程序化生成。

独立黑洞目的地 `black-hole:sagittarius-a` 不替换普通目录系统。存档只保存规范 ID、宇宙版本和玩家状态，不用渲染数据或存档替代世界内容。

旧选种记录说明 `MILKY-038` 曾提供双星、近月、海岸和多类行星的开局节奏；重构改变了生成与表现，不能据此证明它仍是最终最优种子。当前母星半径为 6000 km；旧文的 `planet-0 seaLevelOffset: -420` 已不在当前配置，不再作为事实保留。所有微调以 `world-config.js` 为准。

“最终母星单星”等未交付内容选择保留在[总路线图](optimization-roadmap.md)，在最终筛选时一起满足，不在重构中悄悄更换当前种子。

## 锁的用途与当前状态

`worlds/milky-way.lock.json` 记录出生星系、特殊目的地、邻近 18 系统、64 系统分布、地形/海面/云/星环哨兵、生成器版本与指纹。它是兼容快照，不是运行时世界或完整表面存档。

2026-09-20 复跑 `npm test`：非锁检查通过，旧锁指纹 `1a50259f…` 与当前 `e7f8096f…` 不符；按用户重构指令延期，未刷新锁。不要从旧锁推断当前地形高度或画面。构建状态要区分 `npm run build`（先跑完整 test，会被旧锁阻止）与 `npm run build:pages`（仅静态构建）。

## 重构验收后执行

1. **定筛选标准。** 冻结候选生成器、尺度和体验约束；覆盖出生体验、单/双星策略、海岸地貌、海洋/气候/云系、环境多样性、黑洞周边关系和可探索耗时。
2. **静态筛选。** 当前 `npm run world:curate` 调用 `tools/curate-finite-galaxies.js 256`，输出 `worlds/finite-candidates.json`。静态分数用于缩小范围，不代替画面/游玩。
3. **分清两种截图工具。** `npm run world:curate:shots` 实际调用 `capture-finite-candidates.js`，从候选表取 top12，输出 `docs/curation/finite-galaxy/` 的星图比较；它不是轨道/低飞/地表全套。`node tools/capture-world-candidates.js` 使用 `SEEDS`、`OUT` 等环境变量，输出各候选接触表；它不等待所有地形队列清空，也不能单独作最终验收。
4. **候选完整游玩。** 最终候选另做相同相机/太阳/曝光条件下的轨道、低飞、地表与云海原图、连续下降、导航/登陆/离港、天气演变和性能验证；确认地形构建稳定。旧 `docs/curation/` 图片是历史资料，不是当前版本的复验。
5. **定案与兼容评审。** 更新 `world-config.js` 的最终种子及微调，评估稳定 ID、旧存档/多人重建影响；记录生成器变化、兼容性变化及迁移决定。独立随机命名空间继续优先使用。
6. **有意更新快照。** 运行 `npm run world:lock`，同时导出 catalogue 与 canonical lock；不手工改指纹。
7. **发布回归。** `npm test`、`test:smoke`、`test:full`、相关专项和 `npm run build` 全通过，三处版本同步。记录最终 seed、指纹、commit、代表原图与评审结果。

重筛不得只选一张好看的出生截图，也不能把另一个有限烘焙世界或存档当作替代方案。黑洞、工程设施或渲染改动是否需要更新快照，以实际身份/生成数据变化判断，不作“一定不影响锁”的泛化承诺。
