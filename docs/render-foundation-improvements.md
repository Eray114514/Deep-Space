# 渲染基础改进与交接

更新：2026-10-14。本文维护基础问题、施工顺序和每轮交付边界，供长期任务继续执行。全局画质目标与批次状态见[优化路线图](optimization-roadmap.md)；云、大气、天气与统一时域的规格和进度仍只在[B 计划](cloud-atmosphere-rewrite.md)维护。

## 目标与判断

用户目标是让正常游玩的网页游戏呈现可信的尺度、地貌、光照和细节，视觉目标参考星际公民/无人深空，并使相应成本可承受。2026-10-02 用户授权分轮修复、记录进度，质量优先，不要求一轮做完。2026-10-07 云专项已在 `71769a8` 建立[暂停断点](reviews/cloud-rework-checkpoint-2026-10-07.md)，用户授权先完成底层优化再恢复该专项。暂停的是另一任务的云形态/视觉返工，**不限制基础任务修改云实现**：共享 shader、管线、云调度、缓存、上传和资源生命周期均可直接优化。保留候选云算法和未通过门槛，基础修复不代勾 B4 完成。

底层确实存在会使上层优化失效的问题，已经复现远景植被索引越界和实例大坐标精度风险。还存在整帧资源预算、运动/深度接口、跨尺度阴影与内容表示的缺口。没有证据要求放弃 Three.js/WebGL2；确定性世界、CPU 双精度导航、地形局部网格与连续 LOD、近水局部表示、HDR/PBR/显示变换值得保留。修复共同约定，再逐个迁移消费者，比整库重写更容易定位实际收益。

基础工作不能单独保证目标画质：近景枝叶、树种轮廓、地表材质、覆盖、LOD 和景物照明仍需要 C/R 的内容与呈现升级。增加物理积分样本不能补回缺失的树，也不能替代模型与材质质量。

## 排查依据与未验证部分

- **F1 已复现。** 旧地块键 `(x+512)+(y+512)*1024+(z+512)*1048576` 只支持 x/y 的 `[-512,511]`，母星 `6000000/1024=5859.375`。`(0,5859,0)` 解成 `(0,-285,6)`，并与 `(0,4835,1)` 同键。旧真实玩家取景锚点 `[-2963,5053,134]`，完成缓存 146 块、pending 0，却没有远树；提高实例上限不能解决。
- **F2 排查时数值风险已确认，可见伪影尚未逐项归因。** 当时 `scatter.js` 与 `farflora.js` 的树实例先写入行星尺度 Float32 矩阵；6000000 m 量级间隔为 0.5 m，后续相机相对变换不能恢复丢失的亚米位置。F2a 已迁移远景，近景和地形大坐标材质属性仍需单独处理。不能把此项写成“所有地表抖动已找到唯一原因”。
- **F3 先查真实依赖成本。** 云影准备接收体深度时绘制场景，正式 RenderPass 随后仍绘制场景。F3c 已复用同帧原生阴影图；两次几何/颜色绘制仍存在，是否改为专用深度路径需继续测量。当前低飞的主要 GPU 成本已定位在体积 pass，不能将重复深度绘制当作唯一瓶颈。
- **F4 深度/运动契约要整体迁移。** 当前相机 near 0.12 m、far 1.2e11 m，并使用对数深度；HDR composer 目标 samples=0、已有 SMAA。云 history 的存在不代表所有几何有完整 motion/TAA。不得直接切深度模式或添加第二个 history 所有者；实施规格见[介质、深度与时域接口](medium-render-contract.md)。
- **F5/F6 是表示能力的限制。** 当前主要恒星几何阴影仅覆盖相机附近并随高度关闭；这不等于公里山体/数十公里城市已有完整阴影。旧植被平面着色与经验补亮、水面天空渐变近似等会限制新物理照明效果。是否替换、如何替换，须按玩家质量/成本对照决定。

最初诊断证据在本机 `test-results/foundation-audit-2026-10-02/`；完整运行摘要见 `assessment.md` 与 `report.json`。这些路径被 Git 忽略，长期指令以本文为准。该诊断保留云/HUD/post，但两机位等待 90 s 后生成队列仍未清空，GPU 数据仅用于定位，不能作为稳定性能回归或视觉验收成绩。其他任务持续修改工作树，旧报告须核对源码摘要后使用。

## 2026-10-07 交付：F0 与 F2b

**F0 的根因是 shader 资源所有权错误。** `vclouds=0` 仍生成天气/band 纹理，却没有 `volCloudMat`/共享体积 uniforms。旧地表变体只检查 `cloudSpeciesTex`，因此编译了 sampler3D、sampler2DArray 和 sampler2D 的云分支，却未提供这些 uniforms；真实绘制追踪中它们和方向阴影 sampler 都留在单元 0。不同类型混用使 `drawElements` 返回 1282，地形根本没有成功绘制。初始白灰画面不能据此判断地形材质已经渲染但仅仅不好看。

新增 `hasSurfaceCloudMedium`，shader 定义、地形/水体程序缓存键和绑定源都对齐真实 uniform 所有者；保留 `volCloudUniforms` 的共享源。体积关闭时不编译无主云采样分支，体积开启且有完整所有者时仍使用原算法。没有删云密度/积分、降低云样本数或重新筛世界。

**F2b 的几何、风、压草与阴影共同迁移。** 每个新环在双精度地表原点附近写 Float32 矩阵；提交环、mesh 原点和风相位同步更新，替换尚未完成时保留旧环。植被五个风频率的原点相位分别在 CPU 取周期余数，在局部 shader 继续计算，跨原点保持规范世界相位。压草中心仍以双精度规范行星坐标注入，按当前绘制原点生成 GPU 视图；revision 缓存和可见/阴影 draw hook 覆盖主循环“生成先于交互注入”的顺序，避免使用上一帧中心。

原生方向深度与点光距离阴影材质复用同一 grow/风/压力 hook，并随 mesh 释放；草仍不投射几何阴影。去掉未被任何 shader 消费的 `iAnchor` 属性与提交遍历，减少每个草环约 1.19 MiB CPU 数组；这些数组原先未被激活为顶点输入，不宣称节约同等 GPU 驻留。近景扫描键改为完整有符号元组，播种仍按旧规范坐标与 RNG；树种、密度、尺度和颜色不变。

已增加真实 VolumetricPass 接入与显式 `setLightBatchesEnabled`，候选默认关闭。仅接管单一可见、生产近景、16-anchor、默认回调的云 owner；多 owner、额外回调、其他表示、能力或预算不足均保留完整原路径。来源/程序/尺寸变化会释放或重建私有资源，resize/context loss/dispose 接入原生命周期，借用的几何与物理纹理不由执行器释放。同一个 JS render 中先绑定实际深度、原点/相机和空气 owner，完整提交后才走原 history/组合；没有上一帧查询或跨帧部分发布。

真实玩家路径覆盖 W 移动、变化 jitter、直接原路径、960×540 resize、外来 owner/回调及恢复；动态 HDR 保持原 `.002` 门槛、alpha 精确，少数 RGB 分量有小量差，未写成动态逐位精确或单独归因于舍入。静态 R32F 的额外零差门槛仍独立保留。额外参考绘制/读回扰动了帧率，截图只作接入与构图证据。历史实时 Scene RGB 重复变化、长飞、三档/2K 动态全矩阵、变源/切星与其他 GPU 继续开放。

**另修复了默认路径的历史深度错误。** resize 后 history depth 在 owner framebuffer 再绑定前被采样，而 RenderTarget.setSize 只同步颜色 image，深度按旧尺寸创建不可变 GPU storage。小型 GPU 控制实测 64→32 时 depth 仍分配 64、history FBO 为 36057 / clear GL 1286；实际 pass 切回原路径仍失败。`resizeVolumeHistoryTarget` 在采样前同步 depth image 并标记上传，新控制分配 32、FBO complete、GL 零，真实 resize/原路径控制随后清零错误，未改 vendor。相同尺寸 setSize 保留分批程序，真正尺寸变化仍失效。这项修复默认生效，独立于候选开关。
