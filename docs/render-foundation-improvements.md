# 渲染基础改进与交接

更新：2026-10-02。本文维护基础问题、施工顺序和每轮交付边界，供长期任务继续执行。全局画质目标与批次状态见[优化路线图](optimization-roadmap.md)；云、大气、天气与统一时域的规格和进度仍只在[B 计划](cloud-atmosphere-rewrite.md)维护。

## 目标与判断

用户目标是让正常游玩的网页游戏呈现可信的尺度、地貌、光照和细节，视觉目标参考星际公民/无人深空，并使相应成本可承受。2026-10-02 用户授权分轮修复、记录进度，质量优先，不要求一轮做完；当前不能影响并行云增强工作。

底层确实存在会使上层优化失效的问题，已经复现远景植被索引越界和实例大坐标精度风险。还存在整帧资源预算、运动/深度接口、跨尺度阴影与内容表示的缺口。没有证据要求放弃 Three.js/WebGL2；确定性世界、CPU 双精度导航、地形局部网格与连续 LOD、近水局部表示、HDR/PBR/显示变换值得保留。修复共同约定，再逐个迁移消费者，比整库重写更容易定位实际收益。

基础工作不能单独保证目标画质：近景枝叶、树种轮廓、地表材质、覆盖、LOD 和景物照明仍需要 C/R 的内容与呈现升级。增加物理积分样本不能补回缺失的树，也不能替代模型与材质质量。

## 排查依据与未验证部分

- **F1 已复现。** 旧地块键 `(x+512)+(y+512)*1024+(z+512)*1048576` 只支持 x/y 的 `[-512,511]`，母星 `6000000/1024=5859.375`。`(0,5859,0)` 解成 `(0,-285,6)`，并与 `(0,4835,1)` 同键。旧真实玩家取景锚点 `[-2963,5053,134]`，完成缓存 146 块、pending 0，却没有远树；提高实例上限不能解决。
- **F2 数值风险已确认，可见伪影尚未逐项归因。** `scatter.js` 与 `farflora.js` 的树实例先写入行星尺度 Float32 矩阵；6000000 m 量级间隔为 0.5 m，后续相机相对变换不能恢复丢失的亚米位置。地形位置已局部化，但大坐标材质属性也需单独检查。不能把此项写成“所有地表抖动已找到唯一原因”。
- **F3 先查真实依赖成本。** 并行云影候选在准备接收体深度时绘制场景，正式 RenderPass 随后仍绘制场景。需求合理，成本应合并测量，再评估专用深度路径或其他调度。此观察针对排查时工作树，不宣告正在施工的 B 链设计定案，也不在本轮修改。
- **F4 深度/运动契约要整体迁移。** 当前相机 near 0.12 m、far 1.2e11 m，并使用对数深度；HDR composer 目标 samples=0、已有 SMAA。云 history 的存在不代表所有几何有完整 motion/TAA。不得直接切深度模式或添加第二个 history 所有者；实施规格见[介质、深度与时域接口](medium-render-contract.md)。
- **F5/F6 是表示能力的限制。** 当前主要恒星几何阴影仅覆盖相机附近并随高度关闭；这不等于公里山体/数十公里城市已有完整阴影。旧植被平面着色与经验补亮、水面天空渐变近似等会限制新物理照明效果。是否替换、如何替换，须按玩家质量/成本对照决定。

最初诊断证据在本机 `test-results/foundation-audit-2026-10-02/`；完整运行摘要见 `assessment.md` 与 `report.json`。这些路径被 Git 忽略，长期指令以本文为准。该诊断保留云/HUD/post，但两机位等待 90 s 后生成队列仍未清空，GPU 数据仅用于定位，不能作为稳定性能回归或视觉验收成绩。其他任务持续修改工作树，旧报告须核对源码摘要后使用。

## 本轮交付：F1

范围：只修改 `src/farflora.js` 的地块身份、解码和同距离排序；新增专项测试与本文。地块改用完整 `x:y:z` 字符串；距离排序仍以真实格坐标计算，平局按 z/y/x 排序，保持旧编码有效域内的确定性顺序。分帧构建、缓存、密度、树种、位置种子和生成参数保持原逻辑。键是内存缓存身份，不是保存格式。

测试先在旧实现运行，并在 6000000 m 行星地块壳位置断言失败。修复后 `tools/farfloratest.js` 通过：

- 286000 / 6000000 / 20000000 m 半径，六个轴正负方向、对角线和母星已复现方向；4,139 个发现地块正确，30,998 棵受控森林树位于对应局部地块与地表壳。
- 完整构建与每扫描步暂停/恢复的实例数据完全相同。
- 跨格移动、21.6 km 移动后的淘汰与回访；当前格不被淘汰、缓存回到 384 上限以内，回访树矩阵完全相同。
- 无树生态和淹没地表仍不生成树。测试使用受控生态以隔离索引问题，不能替代真实行星与渲染验证。

浏览器专项 `tools/farfloraplaytest.js` 使用真实母星、正式 HUD/post、固定太阳角与低飞机位，并关闭体积云以隔离并行施工。检查真实远树非空、地块范围、GL/运行时错误，同时在同一动画回调内捕获 OFF/ON/OFF，避免相机、风和几何前进造成差分。报告/截图存于 `test-results/far-flora-player/`。

额外诊断逐 GL 调用归因，在 RenderPass 的地形材质 `drawElements`（索引数 24576，shader 含 `aLocal`/`aLodMorph`/草地材质采样）读到错误；不是远树的实例 draw。记录在本机 `gl-trace.json`，临时追踪会消耗错误标记，其进程退出码不能作为无错误渲染证明。具体非法状态尚未定位，不能断言是某一云改动导致。

因此 **`test:far-flora:player` 最终仍返回失败**，保留整页门槛，不豁免该错误。当前可确认 F1 的索引、树生成、真实可见贡献和独立 GPU 路径成立；不能确认整页渲染健康或整体画质达标。待并行共享着色链稳定后，先复现/修复这个 GL 错误再重跑玩家专项；本轮不修改 `shaders-webgl.js`/`surface-atmosphere.js`/`planet.js` 等共享文件。

**验收边界：** F1 是错误修复，恢复以前缺失的实际绘制负载，不能宣称因此更快。它没有解决 F2 的 Float32 精度，也没有升级树模型、LOD、光照和全云天气性能。正式 2K 全效果与连续飞行性能验收需在相关工作稳定后合流进行。

## 下轮启动条件与具体工作

先读本文、`git status`、C 的要求和当前坐标/介质契约，再核对正在并行修改的模块。下一轮先做 F2 的植被局部坐标：

1. 核对实例、风、交互、阴影、camLocal 与行星旋转的全部坐标消费者。选择局部原点和切换条件；保存/播种坐标保持原来的确定性世界格坐标。
2. 生成矩阵前在 CPU 双精度域减原点，网格父变换补回原点；GPU 使用局部相机/采样坐标，避免 Float32 大数相减。受影响 shader hook 必须一起迁移。
3. 先在一组可复现草地完成近/远树，检查贴地、风和交互、阴影、跨原点/转身/回访；再评估其他景物与材质属性。不要把精度工程顺带变成树种重筛或地形生成改写。
4. 以相同树密度、机位、时间和渲染档位验证实际玩家画面与成本；记录完成/未完成、源码指纹、失败项，提交独立成果后可结束本轮。

当前并行云增强涉及 `main.js`、`planet.js`、共享 shader/管线和 cloud/atmosphere 模块。任何需要修改这些接口的后续工作，先核对最新实现和分工；本轮 F1 不触碰它们。TAA/history 按 B7 的唯一计划推进，其他基础工作消费它的接口。
