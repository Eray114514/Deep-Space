# 渲染基础改进与交接

更新：2026-10-02。本文维护基础问题、施工顺序和每轮交付边界，供长期任务继续执行。全局画质目标与批次状态见[优化路线图](optimization-roadmap.md)；云、大气、天气与统一时域的规格和进度仍只在[B 计划](cloud-atmosphere-rewrite.md)维护。

## 目标与判断

用户目标是让正常游玩的网页游戏呈现可信的尺度、地貌、光照和细节，视觉目标参考星际公民/无人深空，并使相应成本可承受。2026-10-02 用户授权分轮修复、记录进度，质量优先，不要求一轮做完；当前不能影响并行云增强工作。

底层确实存在会使上层优化失效的问题，已经复现远景植被索引越界和实例大坐标精度风险。还存在整帧资源预算、运动/深度接口、跨尺度阴影与内容表示的缺口。没有证据要求放弃 Three.js/WebGL2；确定性世界、CPU 双精度导航、地形局部网格与连续 LOD、近水局部表示、HDR/PBR/显示变换值得保留。修复共同约定，再逐个迁移消费者，比整库重写更容易定位实际收益。

基础工作不能单独保证目标画质：近景枝叶、树种轮廓、地表材质、覆盖、LOD 和景物照明仍需要 C/R 的内容与呈现升级。增加物理积分样本不能补回缺失的树，也不能替代模型与材质质量。

## 排查依据与未验证部分

- **F1 已复现。** 旧地块键 `(x+512)+(y+512)*1024+(z+512)*1048576` 只支持 x/y 的 `[-512,511]`，母星 `6000000/1024=5859.375`。`(0,5859,0)` 解成 `(0,-285,6)`，并与 `(0,4835,1)` 同键。旧真实玩家取景锚点 `[-2963,5053,134]`，完成缓存 146 块、pending 0，却没有远树；提高实例上限不能解决。
- **F2 排查时数值风险已确认，可见伪影尚未逐项归因。** 当时 `scatter.js` 与 `farflora.js` 的树实例先写入行星尺度 Float32 矩阵；6000000 m 量级间隔为 0.5 m，后续相机相对变换不能恢复丢失的亚米位置。F2a 已迁移远景，近景和地形大坐标材质属性仍需单独处理。不能把此项写成“所有地表抖动已找到唯一原因”。
- **F3 先查真实依赖成本。** 并行云影候选在准备接收体深度时绘制场景，正式 RenderPass 随后仍绘制场景。需求合理，成本应合并测量，再评估专用深度路径或其他调度。此观察针对排查时工作树，不宣告正在施工的 B 链设计定案，也不在本轮修改。
- **F4 深度/运动契约要整体迁移。** 当前相机 near 0.12 m、far 1.2e11 m，并使用对数深度；HDR composer 目标 samples=0、已有 SMAA。云 history 的存在不代表所有几何有完整 motion/TAA。不得直接切深度模式或添加第二个 history 所有者；实施规格见[介质、深度与时域接口](medium-render-contract.md)。
- **F5/F6 是表示能力的限制。** 当前主要恒星几何阴影仅覆盖相机附近并随高度关闭；这不等于公里山体/数十公里城市已有完整阴影。旧植被平面着色与经验补亮、水面天空渐变近似等会限制新物理照明效果。是否替换、如何替换，须按玩家质量/成本对照决定。

最初诊断证据在本机 `test-results/foundation-audit-2026-10-02/`；完整运行摘要见 `assessment.md` 与 `report.json`。这些路径被 Git 忽略，长期指令以本文为准。该诊断保留云/HUD/post，但两机位等待 90 s 后生成队列仍未清空，GPU 数据仅用于定位，不能作为稳定性能回归或视觉验收成绩。其他任务持续修改工作树，旧报告须核对源码摘要后使用。

- 无树生态和淹没地表仍不生成树。测试使用受控生态以隔离索引问题，不能替代真实行星与渲染验证。

## 本轮交付：F2a 远景局部精度

运行时只修改 `farflora.js`。每块缓存保存一个双精度地表原点和地块内 Float32 矩阵；树种、尺度、旋转及播种坐标保持原逻辑。生成矩阵前先减原点，重打包时把地块转换到最近已完成地块的绘制原点；mesh 父变换补回原点，GPU 不再相减行星尺度实例位置。相机也在 CPU 减同一原点后上传，保持距离淡出正确。换原点和提交矩阵在一次同步 repack 内完成，未完成的新环继续保留旧环。

近景 `scatter.js`、共享风/压草 hook、地形/云/大气/管线均未修改。下一步 F2b 涉及 `applyWindSway` 的实例位置相位与 `surfaceInteraction` 的位置数组，需要消费者一起迁移；不能只局部化近景矩阵后继续把它与大坐标压草中心比较，也不能使每次换原点都改变风相位。

受控平坦/起伏地形的生成器前后对照（旧版来自提交 `5a4f0f5`）检查 61,996 棵树：完整种类/尺度/旋转数组与双精度种植输入一致，仅存储基准和量化误差改变。最大缓存位置误差如下，不代表所有真实地貌已逐帧验收：

| 半径 | 旧缓存误差 | 新缓存误差 |
|---|---|---|
| 286 km | 15.625 mm | 0.0367 mm |
| 6000 km | 280.718 mm | 0.0335 mm |
| 20000 km | 1099.180 mm | 0.0385 mm |

- **CPU 专项通过。** `farfloraprecisiontest.js` 覆盖三半径、十方向、两地形，共 60 个机位；多地块重打包/原点往返后的最大提交位置误差 0.3382 mm。缓存不被 repack 改写，回到原点后提交数组完全相同，相机原点一致。原索引/流式/淘汰回归仍通过，贴地壳检查收紧到 1 mm。
- **GPU 专项通过。** `farfloragputest.js` 使用生产实例缓冲及 Three.js modelView 变换，独立读回树根/树梢和局部相机距离；包括行星与相机转动、两套绘制原点，共 415,200 样本。RTX 5080 Laptop 最大位置/距离误差 1.081/1.083 mm；SwiftShader 最大 1.262/0.929 mm；均低于 2 mm 门槛，GL/JS error 0。这是数值归因测试，不能替代玩家画面或性能验收。
- **真实玩家局部绘制通过，整页门槛仍失败。** 同一母星、1280×720 Balanced、400 m 低飞、正式 HUD/post、关闭体积云：152 块、24,000 个实例，地形/水体/远树队列清空；OFF/ON 差分 51,075 像素，OFF 重复差分 1 像素；同批生产树 mesh/材质的隔离绘制有 7,685 可见像素、GL error 0。已审阅截图，远树仍可见，proxy 模型质量依然粗糙。整页 OFF/ON/OFF 均为 GL 1282，独立 `farflora=0` 页面也为 1282，无 JS/console error。开始/结束源码一致；证据在 `test-results/far-flora-local-frame-player/`。不放宽 `test:far-flora:player` 的整页 GL 门槛，共享地形绘制错误继续保留为合流阻断。

精度 CPU 回归已接入 `npm test` 与 `test:far-flora`；`npm test` 在旧宇宙锁前的全部检查通过，旧锁失败未刷新。GPU 数据与生成前后对照在本机 `test-results/far-flora-precision/{hardware-gpu,swiftshader-gpu,before-after}.json`；GPU/玩家专项捕获时的运行时摘要为 `f50c7331cc52650cae669f2a6cc966ba6adad76535dd40154a6bd62b96e1f8a0`，各自运行开始/结束一致。收尾时并行工作继续改变全库摘要，上述报告只证明其捕获时版本；后续共享链合流必须重新运行，不能当成最新整页验收。

复现：`npm run test:far-flora`、`npm run test:far-flora:gpu`。后者默认 SwiftShader；设置 `FAR_FLORA_HARDWARE=1` 使用本机 GPU。真实玩家专项可设置 `FAR_FLORA_OUT=test-results/far-flora-local-frame-player` 保留独立证据，再运行 `test:far-flora:player`。

**成本和后续边界：** 每缓存块新增一个 Vector3 原点及一次地形查询，没有每树 Float64 矩阵；重打包新增平移遍历，仍只在原环替换/密度更新时发生。本轮未做正式整帧性能采样，不承诺更快。后续 B7 的前帧矩阵/history 必须处理绘制原点切换，不能把坐标基准变化当成真实运动；本轮不代称 B7 完成。

局部 CPU 归因使用同一页面的真实母星地形、相同地块/实例数，旧生成器取自 `5a4f0f5`，先预热再交替运行。152 个地块的任务初始化，新旧 p95 均约 0.1 ms；24 次完整地块构建的中位数旧 6.7 / 新 7.0 ms，1.25 ms 分片的实测最大值均约 1.3 ms。24,000 个实际实例的 24 次重打包，中位数旧 0.4 / 新 0.5 ms、p95 旧 0.6 / 新 0.8 ms。新增平移有可测 CPU 成本；这些是同步 CPU 局部对照，不含 GPU 上传和正常整帧，不能宣称性能无回退。报告在 `test-results/far-flora-precision/cpu-attribution.json`，源码摘要与上述 GPU/玩家专项一致。

**性能未通过验收。** 两次当前玩家启动的远树最慢流式调用分别约 1.7 ms 与 286.3 ms，后一回重打包最大 1.0 ms。局部 CPU 对照未复现长暂停，成因仍未归因；页面还存在 GL 错误，不能据此排除生成、GC、线程暂停或其他整帧成本。F3 应优先记录连续飞行时的调用栈、GC/调度和 GPU 时间，定位这类长暂停；此处不修改并行管线，也不把异常当作测试噪声删除。
