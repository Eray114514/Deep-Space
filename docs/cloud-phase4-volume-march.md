# 阶段 4：WebGL 云的组织与形态演进

更新：2026-09-30。父计划：[批次 B](cloud-atmosphere-rewrite.md)。文件名保留以兼容既有链接，不表示必须重建 march。本文件维护返工顺序与实施清单；阶段状态见父计划，评审方法见[视觉协议](visual-targets/README.md)。首族与消费者接口见[B4 接线契约](cloud-weather-contract.md)。用户反馈、此前参考使用情况及本轮参考审查见[返工决定](reviews/cloud-visual-rework-2026-09-30.md)。

## 保留什么，必须改什么

历史上用户认可的 WebGL 观感仍是参考，但当前版本的整球云已被用户否定，不能再默认当前“微观雕刻成熟”。只保留在同条件 A/B 中确有收益的细节，允许抽离或替换局部实现。不能把“保护基线”理解成冻结 `densityAt`、壳厚、光学系数和任意截断；这些正是当前影响一致性与写实的部分。

当前 `planet-weather.js` 已将 `src/cloud/weather-system.js` 的真实地形快照接入生产，体积、远云、云影和局部天气共用 atlas。局地低云/LCL 和独立高云高度已接线，母星包络约为 0.25–20.42 km；云种各自的密度/形态与原生天气生灭仍未接入。正确云高须同时解决局地地形、密度尺度、采样与光照，不能把包络当成处处有云。历史天气输入见[天气交接](baselines/b4-weather-2026-09-26/README.md)，当前限制见[局地高度诊断](reviews/b4-local-height-2026-09-27.md)。

局地高度接线曾让无海洋卫星的海面哨兵污染编码范围，形成满屏远云尖刺；已修复并改用独立 RGBA 数据纹理。[修复与门槛](baselines/b4-cloud-geometry-2026-09-27/README.md)要求后续云高改动运行 `test:b4:geometry`，覆盖全星系云壳顶点，不能只测聚焦行星的体积片元。

B5 的积分/联合合成与光照最小闭环已通过，先读[B5 交接](baselines/b5-2026-09-21/README.md)。B4 必须继续使用共同空气传输与恒星功率；当前仍有厚云灰膜、平展顶面和整球花斑，需要从密度/天气组织、自阴影与云内多散射处理，不得恢复旧直射增益或以曝光抹平。现存云 jitter/history 暂成套保留，不另建第二套；统一责任归阶段 7。

## 返工执行顺序

以下四组是执行与交付边界，下面 4A–4F 是覆盖清单，[难度表](remaining-work-difficulty.md)的 B4 编号是细分评估；都不要求逐项停下来汇报。**下一次实现从第 1 组开始，至少形成首族完整成像成果才作为一次交付；诊断、参考取证、调参或截图本身不是新的完成阶段。** 若尚不通过，应明确报告未完成和阻碍，不伪造合格断点。没有要求一次任务跨越全部四组，也不能把“报告一下”误作永久降低验收范围。

### 1. 首族成像返工：从地面到整球都成立

难度 5，覆盖 B4-02/04/07～11 和 B4-03/05 的近远表示部分。目标是同一层积云天气在 S1–S4 具备可信形态、厚薄与光照，消除当前灰膜、块边和涂层感；这一组内连贯解决以下问题：

- **诊断与参考同场。** 固定当前失败的昼夜 S4、三世界样本和代表性侧切/云内机位。打开当前原图并按协议登记；分别隔离天气通道、密度、远云、云光照、空气和曝光，判断块边与灰膜来自哪里。实际运行本地 Aether，补看 three-geospatial 的可用视角；只比较匹配高度/太阳/云种的效果，不因上游缺整球案例而省掉本项目整球检查。
- **明确首族密度。** 在 `src/clouds-webgl.js`、`src/cloud/planet-weather.js` 和 `src/cloud/cloud-species.js` 分开云区覆盖、米制胞状尺度、垂直 profile、细节侵蚀和消光。优先用 three-geospatial 的层/shape/detail 分离及本地 demo 的密度组织作候选，HPVolumeCloud 补充形态；先做少量可归因 A/B，选定后再整合。验收依据是胞状、孔隙、自然边缘和侧切厚度，不是增加噪声层数。
- **采样与光照一起校准。** 在生产 GLSL 增加可读回的密度/柱透射/实际步数诊断；固定薄层、厚层、掠射与受控 slab/球团。建立高样本或独立积分参考，预先写明误差指标/阈值后再调算法；参考自身也做加倍采样收敛，不能只对照另一档同样漏采的 march。替换无依据的 `thick*3.2` 截断；保守跳空、足迹过滤、近远阴影表示按误差与成本选择。比较完整太阳光程与多八度散射近似，保留 B5 的双星功率/空气透射，限制经验项并避免重复补光。
- **整球表示同步修。** `src/shaders-webgl.js` 的远云必须与首族占用、云高和主要柱透射一致；否则 S4 看不到主体积的改进。关闭单一路径做归因后必须恢复正常合成；不能用关远云/关体积作为验收方案。

出组条件：三世界的首族样例在昼暮夜、S1–S4、侧切和连续穿云经原图/动态评审，无当前明显缺陷；有单帧收敛与正常 history 对照、阴影侧及双星检查、三档内容一致和首轮硬件成本。`test:b4:contract/weather/geometry/optical`、B5 受影响回归、`npm test`、大改后的 smoke 均有范围明确的结果。整帧预算沿用父计划，不能只报 HUD FPS；若只做部分性能采样，明确未通过完整预算。更新参考采用记录、实际阈值、内容版本和证据，不提前关闭 C1 或 B4。

### 2. 首族跨消费者与动态天气闭环

难度 5，依赖第 1 组，覆盖 B4-02/05/06/07/11 的余项。沿 `planet-weather.js`、`weather-system.js`、`shaders-webgl.js`、`Planet.weatherAt/cloudTransit`、水面环境输入及 `weather-effects.js`：

- 将逐星云影的高度/光程、远云透射、水面云反射、局部能见度/降水对齐首族；比较同点/同柱，不能只确认引用了同张纹理。首族水面样例在本组闭环，B6 再扩全部场景与反射/折射组合。
- 完成天气生灭、风切变、对当前海岸/山地的响应，替换初始快照刚性平流的限制；用同一绝对时钟测试冻结、推进、回溯与重载，不每帧重校覆盖。
- 固定晴空/云区/锋面/眼墙/副高/海陆案例并逐个看图；同时统计最终光学覆盖、透明薄云比例与晴空连通性。

出组条件：首族在多方位连续轨道—地面往返中，看到的云、阴影、反射与进入云/雨的实际位置一致，切换质量不换天气；动态天气没有跳变/呼吸且可重建。相关 C1/C4/C5 子集有证据，完整契约仍等待所有云族和 B6。必要的 B5/几何/资源回归继续保留。

### 3. 扩展云族与垂直天气结构

难度 4～5，依赖首族两组通过，覆盖 B4-03/12～23。按下方 4C 清单，成组扩展层状低云/积云 → 深对流及关联砧顶 → 中高薄云 → 雾/夜光云；顺序可因实测风险调整，但不把 16 个名称一次性塞进同一通用密度。

主要触点是云种/天气数据、生产密度/照明及所有消费者。每组必须在侧切、云下/内/上、远景和对应光照条件可辨，验证薄层漏采、高山穿云、层间重叠、日夜可见性和增量成本；把本地 HPVolumeCloud 的形态候选逐项落实为采用/放弃记录。占用体/新纹理只有测得收益才接入，采用时同步交付真实 WebGL 上传、代际与释放，不把生命周期留给未来猜测。

出组条件：父计划全部云族与特殊路径都有自己的可辨证据，不同天气组合自然，既有首族不退步；没有靠高云/雾整球发光或白膜填覆盖率。云种内部的低层细分用于难度估计，不强制每个云名停一次。

### 4. 整体调校、回归与 B4 收尾

难度 4，依赖前三组，覆盖 B4-24 及各组最终回归。按 4F 和视觉协议完成当前源码的全矩阵、正常玩家连续过程、性能与生命周期证据，复查全部有云天体、无海洋卫星、双星/日食、远端/门户相关路径及前景遮挡。

对“星球仍不写实”的残余问题逐项归因：若是本阶段云的问题，继续修；若证实是空气/合成缺陷，重开 B5 对应项并修复；若是全局反射、PBR 或时域的独立欠项，写明 B6/R/B7 责任与可复现证据，不声称最终整球已通过。B4 本身的明显缺陷不能这样转移责任。

出组条件：4F 的 B4 范围通过并有用户实际确认，更新父计划唯一进度表和难度余项，提交实现/文档/证据；B6/B7/B8 仍按各自范围验收。本地未归档截图、未来 TAA、参考项目效果都不能代替本次结果。

### 共同执行约束

基础工具复用 `test:b0:baseline`（多机位生产画面）、`test:b5:player`（B5 玩家链）、`test:b4:geometry/optical/perf` 等；先核对实际覆盖范围再补首族侧切、高样本与动态记录，不假设某一个脚本已经覆盖整个矩阵。新诊断优先围绕真实失败，避免只测试实现的自洽。

每次改动都登记源码/参考版本、采用算法、数值和画面收益、成本及剩余问题。最初保留的小样本/错误阈值不能不断放宽来换 PASS。高风险密度、采样和光照工作尽量连续由同一 agent 推进；代码仍可按逻辑分提交，不等于对用户逐次停工汇报。

- [x] 定义稳定世界坐标、绝对天气时间、米制高度、每米消光、场版本与消费者接口；B4-01 已提供真实地形查询与固定点验证。这里关闭的是接口定义，生产密度跨相机/档位一致仍由 4B/4D 验证。
- [x] 移除相机相关厚度映射及逐射线天气遮罩；生产 GLSL 在薄/厚包络固定世界点保持不变，有非空与旧算法坏例控制。见[修复交接](reviews/cloud-atmosphere-foundation-2026-09-20.md)。跨消费者/档位积分一致性仍待闭环。
- [ ] 低/高云高度已拆开；中层、雾、夜光云及全部云种的局地地形遮挡仍须定案，不使用“全星球最高山+常数”作为统一云底。

### 4B：先做一条生产闭环

- [x] 生产宏观天气只保留一个输入所有者，真实地形参与初始快照；共享 atlas 实际接到体积、远云和局部天气，修复云影误读类型通道、极点坐标和 fixture 重绑。此项只关闭输入迁移，不替代下列首族/C1 验收。
- [ ] 首族为层积云，接入行星尺度晴空区、锋面、气旋/眼墙、副高和海陆差异；微观 3D 雕刻按跨高度 A/B 决定保留或替换。
- [ ] 同一状态贯通体积云、太空解析表示、云影、水面反射与降水/能见度。高度与天气输入已共享，柱消光、逐星阴影与反射还未一致。先以少量固定世界点证明 C1，再扩种类。
- [ ] coverage 控制“哪里有云”，云内密度/消光控制厚薄；保持云区空隙。不能以整层白膜补足全球覆盖率。
- [ ] 冻结时间验证轨道—低空一致，再推进绝对时间验证风平流、天气更新连续、重载一致；避免每帧重新校准覆盖率造成云系呼吸。

### 4C：扩展全部云种与垂直差异

- [ ] 低/中/高族各有覆盖、水平尺度、局地底/顶、垂直 profile、消光与风切变，再扩到父计划要求的具体云种。
- [ ] 对流云由局地不稳定度/湿度决定纵向发展；积雨云及其砧顶有关联，不能无母体生成砧顶。
- [ ] 层积云扁平胞状有孔隙；层云/雨层云允许平展；积云有团块/塔体；高云有薄层/纤维；荚状云有地形与风条件。不能强迫所有云都像花椰菜。
- [ ] 同种云整体高度与厚度分别变化，云底/云顶不独立抖到互穿；局地 LCL/地形抬升使地面视角可区分区域。
- [ ] 雾、夜光云独立接入，并与照明/温湿/高度条件一致；撤除假整球后仍欠真实夜光云，不能标作该功能完成。
- [ ] 侧切面、云下/内/上及远景均可辨云族；完成要求是画面形态，不是权重表含 16 个名称。

可选形态参考：高云 UV warp、层积云胞厚薄、云底平滑、覆盖变化下的云顶形态、分云种侵蚀。每次只试一个可归因改动，多场景提升才保留；不把 HPVolumeCloud 的 6 km 阴影距离、3 km 高云光程或固定几何步比当通用常数。

### 4D：采样、光照与性能

- [ ] 步长按真实被解析特征与射线穿段决定，长切线不因最大步数封顶退化到公里级漏采。CPU 的每薄层 ≥4 点只是防漏采下限；还需生产 GLSL 的质量阶梯/高样本参考。
- [ ] 术语纠正：400 m 特征 `/5 = 80 m` 是步长**上限**（最多跨多远），不是不得更小的下限。掠射穿薄壳的有效光程须按实际球壳计算，不能保证所有擦边射线都有四个内部样本。
- [ ] 生产局地层已改米制低/高消光，旧 fixture 仍用 `sigma = 3.80 / thick`；`t1 = min(t1, t0 + thick*3.2)` 仍在生产。长路径裁剪须有剩余透射/辐射误差界，不能为保持临边孔隙任意丢弃远端云；直接删除曾造成严重帧时回退。
- [ ] 自阴影使用同一密度场的太阳光程；逐星直射、空气透射、天空/多散射分别定义。删除用直射保底或显示白点硬裁代替介质照明的最终验收口径，重新校准 HDR 与 R 的曝光/bloom。
- [ ] 单次散射、双叶 HG、多八度散射近似作为可比较方案；先用 slab/球状介质参考、参数扫和多场景 A/B 再选。phi_fwd 默认不进入生产，无独立收益/能量证据不保留，也不与其他高阶近似盲叠。
- [ ] 在接入每一族时测质量与 GPU 成本，不能到阶段 7 才第一次发现多层预算不可用。记录实际执行步数、漏采和透射误差，不只记录 `uMaxSteps`。

### 4E：按需迁移 CPU 工具箱

| 工具 | 已有价值 | 接生产前必补 |
|---|---|---|
| `weather-system.js` / `cloud-species.js` | 宏观天气已通过真实地形快照进入生产；云种/高度仍为候选数据 | 天气生灭与当前地形响应、局地 band、米制密度与可辨形态 |
| `cloud-density.js` | 烘焙场、CPU 介质与积分覆盖参考 | 若消费这些场，GLSL 采样/坐标/消光 readback；共享纹理不自动保证一致 |
| `cloud-occupancy.js` | CPU 保守占用与裁剪/步长规划 | 仅实测收益足够时接；GPU 跳过不得漏云，成本与上传一起算 |
| `cloud-resource-manager.js` / worker | 取消、缓存、代际/原子交换模型 | 当前 WebGL 整纹理上传的帧时、恢复/释放；旧 WebGPU 分片路径及模拟上传测试不能代替 |

允许采用更轻的连续参数表示，不要求为了复用旧资产先承担整套 3D 纹理成本。若接新场，父计划的资源预算与 WebGL 验证立即生效。
