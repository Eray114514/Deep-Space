# 阶段 4：WebGL 云的组织与形态演进

更新：2026-09-26。父计划：[批次 B](cloud-atmosphere-rewrite.md)。文件名保留以兼容既有链接，不表示必须重建 march。本文件只维护云的实施清单；阶段状态见父计划，评审方法见[视觉协议](visual-targets/README.md)。首族与消费者接口见[B4 接线契约](cloud-weather-contract.md)。

## 保留什么，必须改什么

保留用户认可的 WebGL 云微观形态、体积明暗与视觉细节作为起点，允许根据实际缺陷抽离或替换局部实现。不能把“保护基线”理解成冻结 `densityAt`、壳厚、光学系数和任意截断；这些正是当前影响一致性与写实的部分。

当前 `planet-weather.js` 已将 `src/cloud/weather-system.js` 的真实地形快照接入生产，体积、远云、云影和局部天气共用 atlas。原生天气生灭、云种局地高度与密度仍未接入。母星当前云包络仍为 12–53.56 km；旧 12–91.8 km 与 230–420 km 都不再是当前画面事实。正确云高不能靠把全部云挤回 1–16 km 得到，须同时解决局地地形、密度尺度、采样与光照。迁移表示与证据见[天气交接](baselines/b4-weather-2026-09-26/README.md)。

B5 的积分/联合合成与光照最小闭环已通过，先读[B5 交接](baselines/b5-2026-09-21/README.md)。B4 必须继续使用共同空气传输与恒星功率；当前仍有厚云灰膜、平展顶面和整球花斑，需要从密度/天气组织、自阴影与云内多散射处理，不得恢复旧直射增益或以曝光抹平。现存云 jitter/history 暂成套保留，不另建第二套；统一责任归阶段 7。

## 实施清单

### 4A：基线与不变量

- [x] B0/B5 已冻结三世界昼暮夜的正常/关空气/关云 S1–S4、侧切与连续升降基线，带源码摘要。B4 每次改变云场后用 `test:b5:player` 同协议重采，并新增所接云族的独立场景。
- [x] 定义稳定世界坐标、绝对天气时间、米制高度、每米消光、场版本与消费者接口；B4-01 已提供真实地形查询与固定点验证。这里关闭的是接口定义，生产密度跨相机/档位一致仍由 4B/4D 验证。
- [x] 移除相机相关厚度映射及逐射线天气遮罩；生产 GLSL 在薄/厚包络固定世界点保持不变，有非空与旧算法坏例控制。见[修复交接](reviews/cloud-atmosphere-foundation-2026-09-20.md)。跨消费者/档位积分一致性仍待闭环。
- [ ] 明确低/中/高/特殊云的局地地形遮挡和高度基准，不使用“全星球最高山+常数”作为统一云底。

### 4B：先做一条生产闭环

- [x] 生产宏观天气只保留一个输入所有者，真实地形参与初始快照；共享 atlas 实际接到体积、远云和局部天气，修复云影误读类型通道、极点坐标和 fixture 重绑。此项只关闭输入迁移，不替代下列首族/C1 验收。
- [ ] 选低云族，接入行星尺度晴空区、锋面、气旋/眼墙、副高和海陆差异；保留已经好的微观 3D 雕刻。
- [ ] 同一状态贯通体积云、太空解析表示、云影、水面反射与降水/能见度。先以少量固定世界点证明 C1，再扩种类。
- [ ] coverage 控制“哪里有云”，云内密度/消光控制厚薄；保持云区空隙。不能以整层白膜补足全球覆盖率。
- [ ] 冻结时间验证轨道—低空一致，再推进绝对时间验证风平流、天气更新连续、重载一致；避免每帧重新校准覆盖率造成云系呼吸。

### 4C：扩展全部云种与垂直差异

- [ ] 低/中/高族各有覆盖、水平尺度、局地底/顶、垂直 profile、消光与风切变，再扩到父计划要求的具体云种。
- [ ] 对流云由局地不稳定度/湿度决定纵向发展；积雨云及其砧顶有关联，不能无母体生成砧顶。
- [ ] 层积云扁平胞状有孔隙；层云/雨层云允许平展；积云有团块/塔体；高云有薄层/纤维；荚状云有地形与风条件。不能强迫所有云都像花椰菜。
- [ ] 同种云整体高度与厚度分别变化，云底/云顶不独立抖到互穿；局地 LCL/地形抬升使地面视角可区分区域。
- [ ] 雾、夜光云独立接入，并与照明/温湿/高度条件一致；撤除假整球后仍欠真实夜光云，不能标作该功能完成。
- [ ] 侧切面、云下/内/上及远景均可辨云族；完成要求是画面形态，不是权重表含 16 个名称。

可选形态参考：高云 UV warp、层积云胞厚薄、云底平滑、覆盖变化下的云顶形态、分云种侵蚀。每次只试一个可归因改动，多场景提升才保留；不把 HPVolumeCloud 的 6 km 阴影距离、3 km 高云光程或固定几何步比当通用常数。

### 4D：采样、光照与性能

- [ ] 步长按真实被解析特征与射线穿段决定，长切线不因最大步数封顶退化到公里级漏采。CPU 的每薄层 ≥4 点只是防漏采下限；还需生产 GLSL 的质量阶梯/高样本参考。
- [ ] 术语纠正：400 m 特征 `/5 = 80 m` 是步长**上限**（最多跨多远），不是不得更小的下限。掠射穿薄壳的有效光程须按实际球壳计算，不能保证所有擦边射线都有四个内部样本。
- [ ] 审查 `sigma = 3.80 / thick` 与 `t1 = min(t1, t0 + thick*3.2)`：同一介质不能因观察者改变消光，长路径裁剪须有剩余透射/辐射误差界。不能为保持临边孔隙任意丢弃远端云。
- [ ] 自阴影使用同一密度场的太阳光程；逐星直射、空气透射、天空/多散射分别定义。删除用直射保底或显示白点硬裁代替介质照明的最终验收口径，重新校准 HDR 与 R 的曝光/bloom。
- [ ] 单次散射、双叶 HG、多八度散射近似作为可比较方案；先用 slab/球状介质参考、参数扫和多场景 A/B 再选。phi_fwd 默认不进入生产，无独立收益/能量证据不保留，也不与其他高阶近似盲叠。
- [ ] 在接入每一族时测质量与 GPU 成本，不能到阶段 7 才第一次发现多层预算不可用。记录实际执行步数、漏采和透射误差，不只记录 `uMaxSteps`。

### 4E：按需迁移 CPU 工具箱

| 工具 | 已有价值 | 接生产前必补 |
|---|---|---|
| `weather-system.js` / `cloud-species.js` | 宏观天气已通过真实地形快照进入生产；云种/高度仍为候选数据 | 天气生灭与当前地形响应、局地 band、米制密度与可辨形态 |
| `cloud-density.js` | 烘焙场、CPU 介质与积分覆盖参考 | 若消费这些场，GLSL 采样/坐标/消光 readback；共享纹理不自动保证一致 |
| `cloud-occupancy.js` | CPU 保守占用与裁剪/步长规划 | 仅实测收益足够时接；GPU 跳过不得漏云，成本与上传一起算 |
| `cloud-resource-manager.js` / worker | 取消、缓存、代际/原子交换模型 | 当前 WebGL 整纹理上传的帧时、恢复/释放；旧 WebGPU 分片路径及模拟上传测试不能代替 |

允许采用更轻的连续参数表示，不要求为了复用旧资产先承担整套 3D 纹理成本。若接新场，父计划的资源预算与 WebGL 验证立即生效。
