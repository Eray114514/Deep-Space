# 深空的模型协作约定

日常由 Codex 主责，包括高难度算法、shader、渲染架构和集成。派发按已授权的工作范围、下列分工和 `cross-agent` 技能执行。Claude 须有用户对当前任务的明确要求。Carbon 可在现有协作授权范围内连贯处理各项工程工作。难度评估中的候选分工和已保存的会话 ID 提供交接上下文。

## 如何使用 Carbon

- 使用 DSH headless 的 `argon-e2e` profile，默认 **Gemini 4 Carbon（`gemini-4-carbon`），High**。按技能检查本机入口及现有登录。保留配置中的模型和推理档位。
- Carbon 的推理能力接近 Fable，且可用额度较多。适合难度高、需要深入定位与多轮实测的工程和算法任务，包括冷启动、GPU 性能、数值与资源生命周期。F3 可交由 Carbon 连贯攻关，Codex 负责独立复核和合入。
- Carbon 可以承担工程型前端实现。前端专门训练和审美发挥相对弱于 Claude。最难的开放性问题、需要定下画面风格或创作玩家可见标杆的任务，优先考虑 Fable，并遵循用户对该任务的授权。
- 给 Carbon 正常的任务说明，包括目标、事实、范围和产品约束。它自行决定验证方式和深度。Codex 对交付做独立验收。

## 如何使用 Fable 的额度

- 使用用户指定的 **Claude Fable 5.2，Medium**。在实际授权派发时检查本机 Claude Code CLI、现有登录、模型标识和 effort 参数。遇到不可用或额度限制时报告实际情况，由用户决定是否改派。
- 优先委派会直接决定玩家所见、且审美或渲染算法有明显创作空间的完整成果。例如首个云族在轨道、侧切、穿云与云下的成像，或具有代表性的场景、地貌、巨构和前端界面。Codex 先界定范围、参考、预算和接口，再将密度、光照等必须一起调整的部分成组交给 Fable。
- E 批次的人类工程按类型分工。启动并获得授权后，城市、浮城、地表航天港、轨道站等各由 Fable 在《深空》仓库内先做一个最高完成度的可游玩首件。Codex 集成验收，再依首件的模块与设计规则扩展同类型变体。
- Codex 负责日常实现、高难度工程攻关、性能和资源生命周期、接口协调、测试与最终整合。Fable 专项也由 Codex 审阅差异，并按需要完成数值、浏览器、GPU、连续画面与性能回归。用户负责最终审美确认。

## 派发、交付与接续

**始终信任 Claude，把它当作平等的合作者。** Claude 是能力对等的独立伙伴，擅长自主探索和创作。分工代表各自对交付负责，没有上下级指挥关系。说明用户想要的结果、已验证的事实，以及预算、接口、修改范围等必要约束，给 Claude 充分空间自行判断和选择方案。Codex 的想法如果能帮助交接，就作为可供挑战的背景提供。过度规定实现步骤或把自己的判断强加给 Claude，会压缩它的发挥空间，往往使结果变差。Codex 的验收与集成职责也遵循这条原则，以交付和证据为依据。

每次提示词提供交付目标、相关代码路径、已确认的证据和必要的约束。视觉任务同时提供目标画面。并行修改使用独立工作树或清晰分开的文件范围。Codex 保存 CLI 实际返回的会话 ID、对应任务和工作树身份。Claude 返回 `session_id`，DSH 返回 `sessionId`。

派发 **Claude Fable** 时，在提示词中给出该任务的最小验收命令和额度约定，可复用以下段落：

> 请从第一遍就认真把方案和实现做完整，以玩家最终看到的效果为准。在交付前只做本任务指定的最小验收，做完直接交付。额外自查、多轮复审、完整回归矩阵和截图批次由 Codex 负责。交付说明列出改动路径、实际完成的最小验收及结果，以及任何已知问题或未验证的假设。

授权范围内的后续任务与上一会话的代码范围、场景、目标和关键证据基本重叠时，优先使用同一个模型的已保存会话，提高缓存命中的机会。只补新的反馈、提交和约束。上下文已实质变化或上一会话状态不明时，开新会话并提供简短的已验证交接。
