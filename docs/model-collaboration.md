# 深空的模型协作约定

适用于本项目当前与后续的协作。每次委派以用户对当前任务的明确授权为准。日常由 Codex 主责，大部分工程和视觉实现都可由 Codex 完成，包括高难度算法、shader 和渲染架构。只有用户明确要求使用 Claude 协作时才读取本约定并按 `cross-agent` 技能派发。难度评估中的候选分工、以往的协作授权和已保存的会话 ID 均只提供上下文。

## 如何使用 Fable 的额度

- 使用用户指定的 **Claude Fable 5.2，Medium**。在实际授权派发时检查本机 Claude Code CLI、现有登录、模型标识和 effort 参数。遇到不可用或额度限制时报告实际情况，由用户决定是否改派。
- 优先委派会直接决定玩家所见、且审美或渲染算法有明显创作空间的完整成果。例如首个云族在轨道、侧切、穿云与云下的成像，或具有代表性的场景、地貌、巨构和前端界面。Codex 先界定范围、参考、预算和接口，再将密度、光照等必须一起调整的部分成组交给 Fable。
- E 批次的人类工程按类型分工。启动并获得授权后，城市、浮城、地表航天港、轨道站等各由 Fable 在《深空》仓库内先做一个最高完成度的可游玩首件。Codex 集成验收，再依首件的模块与设计规则扩展同类型变体。
- Codex 负责日常实现、高难度工程攻关、性能和资源生命周期、接口协调、测试与最终整合。Fable 专项也由 Codex 审阅差异，并按需要完成数值、浏览器、GPU、连续画面与性能回归。用户负责最终审美确认。

## 派发、交付与接续

**始终信任 Claude，把它当作平等的合作者。** Claude 是能力对等的独立伙伴，擅长自主探索和创作。分工代表各自对交付负责，没有上下级指挥关系。说明用户想要的结果、已验证的事实，以及预算、接口、修改范围等必要约束，给 Claude 充分空间自行判断和选择方案。Codex 的想法如果能帮助交接，就作为可供挑战的背景提供。过度规定实现步骤或把自己的判断强加给 Claude，会压缩它的发挥空间，往往使结果变差。Codex 的验收与集成职责也遵循这条原则，以交付和证据为依据。

每次提示词提供清晰的交付目标、相关代码路径和已确认的证据、目标画面、必要的约束，以及最小验收命令。采用技能要求的 CLI 调用方式。并行修改使用独立工作树或清晰分开的文件范围。Codex 保存实际返回的 `session_id`、对应任务和工作树身份。

在提示词中明确额度约定，可直接复用以下段落：

> 请从第一遍就认真把方案和实现做完整，以玩家最终看到的效果为准。在交付前只做本任务指定的最小验收，做完直接交付。额外自查、多轮复审、完整回归矩阵和截图批次由 Codex 负责。交付说明列出改动路径、实际完成的最小验收及结果，以及任何已知问题或未验证的假设。

授权的后续任务与上一会话的代码范围、场景、目标和关键证据基本重叠时，优先用保存的 `session_id` 接续同一个会话，提高缓存命中的机会。只补新的反馈、提交和约束。上下文已实质变化或上一会话状态不明时，开新会话并提供简短的已验证交接。保存会话 ID 用于接续，派发授权仍以本次用户要求为准。
