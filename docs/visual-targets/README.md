# 云与大气视觉验收协议

本文件是 B 的唯一视觉评估协议；[实施计划](../cloud-atmosphere-rewrite.md)定义功能与光学合同。图片是用户提供的开发/验收参考，不作为游戏素材或宣传图片。目标是形态、光照、尺度与融合质量，不复制地理形状、构图或逐像素颜色。

## 机位与样本

| 场景 | 参考 | 捕获要求 |
|---|---|---|
| S1 地面仰视 | 无固定目标图 | 局地地表站立，仰角约 45°；天空特写外再保留含山体/树木/玩家前景的正常画面，以发现天花板和遮挡问题 |
| S2 云内到云上 | [云海之上](星际公民_目标比对/体积云_云海之上.png) | 云下、云内、云顶上方约 1.5 km，平视/略下俯；连续穿越并包含侧切面 |
| S3 低轨斜视 | [太空云层](星际公民_目标比对/星际公民_太空云层.jpeg) | 6000 km 行星可从约 400 km 起调，弧形地平线与逆光云海同框；保存太阳方向与 FOV |
| S4 整球 | [远眺](星际公民_目标比对/星际公民_远眺.png) | 距地心约 2.2R 起调、看向地心；满相/侧光/晨昏/夜侧分别捕获 |

[orbital-clouds-reference.png](orbital-clouds-reference.png) 作为补充尺度/构图参考，不能覆盖 S1–S4。上述距离是取景起点，不是通过门槛；以真实运行高度和云顶为准，禁止取错景后仍以标签宣称已验收。

至少三个独立天气种子/实例，每个覆盖四场景和昼/暮/夜；另选晴空、薄层、厚对流及不同气压/行星尺度。固定天气/天体时刻、曝光、太阳方向、绘制尺寸、DPR 和自适应状态做归因 A/B；再恢复正常时间/自动曝光和实际输入验证体验。

每组都要有 `post=1`、正常 HUD/玩家前景的最终链；隐藏 HUD 和关闭大气/云只作辅助归因。`cloudvisualdiag.js` 目前尚未完整覆盖此矩阵，不能仅凭脚本运行成功勾选全部场景。

## 五维评审

1. **形态结构**：团块/纤维/胞状是否符合云种，有无规则重复、接缝和不自然锐边。
2. **体积与连续性**：云底、云顶、自遮挡、侧切面、穿入/穿出是否连贯，有无贴片和视角变形。
3. **光照**：太阳方向、双星、银边、阴影、日食、亮暗过渡是否一致；真实云底阴影允许深暗。
4. **色彩与融合**：远云空气透视、日落、地表/水面/前景遮挡、曝光和大气临边是否自然；有无蓝幕、灰膜、描边。
5. **尺度与天气组织**：大片晴空和天气系统、云区内空隙、层间关系与可探索高度是否成立；不同位置不是同一种花斑。

每条缺陷标注场景、可定位区域、严重度、复现状态和证据。无致命/明显缺陷才进入最终用户实机验收；细微差距也记录，不能只写“AAA PASS”。独立评审如被安排可辅助找盲点，但不能替代证据或用户审美裁决。

**取消“模型猜错来源连续两次”与“被判为现实照片”门槛。** 来源竞猜与真实画质没有可靠的一一对应；可选盲评只把具体理由转成缺陷，不以猜对/猜错决定完成。也不排除云分布和构图中与尺度/体系有关的问题，否则会漏掉用户最关心的 S3/C5。

## 动态、数值与性能

- 静止测试冻结所有相关状态；动态测试包含慢扫、大幅转镜、平移、穿云、反遮挡、切星和 resize。图像差分需剔除正常位移影响，另查拖影/模糊；同姿态回访只证明确定性。
- 覆盖率用最终介质透射/遮挡与等面积球面统计，记录阈值和薄云比例；不能从白色像素数或天气代理直接宣布达标。
- 保留薄临边、黑描边与前景遮挡坏例作为负例。只对特定满相 fixture 使用“临边应增亮”的回归阈值，不能禁止所有视角真实消光。
- 2560×1440 Ultra 记录完整样本 p95、1% low、长帧、GPU 云/大气开关差及资源创建；目标硬件与门槛见[总路线图](../optimization-roadmap.md)。中低档不得改天气内容或关闭整个体积路径冒充优化。

## 记录格式

一轮一条 manifest：源码 commit/摘要、天体 ID/种子、相机位置/FOV、天气/天体时间、太阳方向、GPU/浏览器、CSS 与 drawing buffer 尺寸、DPR/档位、自适应/曝光状态、原图/连续帧路径、数值与帧时、五维缺陷、修复及剩余项。不可用过期报告证明当前源码。

本机 `test-results/` 不是永久归档。关闭阶段时把关键 manifest 与代表性原图保存到可随项目获取的位置或稳定产物链接；在此之前明确证据仅本机可用。
