# 脉冲、跃迁与弦界航道重做

2026-11-17 开工。目标：电影级、写实、过渡无缝。用户原话的三条硬要求：

- 脉冲像一次小型折跃，结束后感觉是"跳过去了"，而不是加速飞了一段；第一人称连按不能抖。
- 跃迁先是星点拉长，再丝滑进入一条超长时空通道（此时没有星点），走完后星点从拉长恢复，目的地出现。效果要好看不廉价，各阶段之间不能有"一个特效没了、下一个出来"的断层，星球不能突然飞到面前。
- 弦界航道是两个空间的遮挡（空间折叠），透过去看要像空间真的在面前，穿过去不能"小变一下"。它以后要复用到竞速关卡的小传送门、手动开门直达地表等场景，形态必须可调。

## 共同底座（已完成）

- **一条时间线**：[transit.js](../src/transit.js) 是纯函数编排。脉冲和跃迁的星流长度、像差、隧道密度、入口/出口深度、FOV、镜头推背、船体光照全部读同一组通道，阶段交接只是同一组参数连续变化。`tools/test.js` 以 1/120 s 步长检查每个通道在全时段都没有跳变。
- **真实星流**：[starflow.js](../src/starflow.js) 把目录恒星和银河背景星从点精灵换成可拉伸的胶囊。静止时与原来的圆点逐像素等价；运动时头部是恒星的相对论像差方向、尾部是更高 β 下的同一颗星，所以星星向消失点聚拢并向外拉出拖尾，前方蓝移、后方红移。拉长的就是天上真实的星。
- **过渡通道**：[transit-shader.js](../src/transit-shader.js) 在场景光照之后、前景船体之前运行：场景径向运动模糊；脉冲的空间收缩与折射冲击环；跃迁隧道按像素做"射线与弯曲管道"求交（粗搜索加二分），入口和出口都是管道里的深度平面，所以入口从中心向外扫开、出口从中心向外打开，是几何上自然发生的，而不是两层画面交叉淡化。
- **镜头语言**：去掉所有高频正弦抖动，只保留一次低频推背回弹（座舱内幅度约为第三人称的 8%）。
- **船体光照**：两盏常驻的前景层灯（强度为 0 时不改变灯光数量，避免切换时重编译着色器）给船体打出口光和隧道环境光，隧道里同时压暗恒星主光。

## 脉冲（第二轮完成，待用户实机确认）

约 1.15 s：蓄能 0.2 s（视野微收、星点开始拉长、中心轻微吸入）→ 折跃（约 80% 的位移集中在 0.22–0.34 s，正是星流最长、空间最压缩的窗口）→ 释放（星条带回弹、冲击环向外扩散）。结束后速度原样交还，不再补到加力上限。上一跳落地后（0.4 s）即可再按，前一跳的释放作为余波继续播完，画面不会重置。

**长按蓄力**（11-17 用户要求）：短按（< 0.18 s）是普通折跃。按住时，时间线停在起跳前，蓄力在约 1.6 s 内充满：星点向前聚拢、视野收紧并轻微呼吸、船体被照亮、蓄能音调上升。松开后，按蓄力折跃最多 8 倍距离，燃料消耗最多 2.5 倍，蓄力上限受剩余燃料限制。朝地形方向的远跳最多只走高度的三分之一。契约在 `pulseChargeFromHold` / `pulseChargeScaling`，音效为 `pulseCharge`（持续音）加按力度缩放的 `pulse`。

## 跃迁（第二轮完成，待用户实机确认）

五段，见 `warpPlan`：A 蓄能 3 s、B 入隧 1.25 s、C 隧道 4–8 s（随距离）、D 出隧 1.2 s、E 制动 3.2 s。

- 目的地在隧道完全不透明后 0.5 s 才接管，并在此时清空时域历史。再过 0.6 s，目的星球的大气、云和海洋就开始渲染，所以出口打开、星球变大的过程中不会再突然冒出东西。
- 出隧前相机已放在目标行星约 38 倍构图距离处，并且已经朝向它。出口打开时行星是消失点处的一个亮点，随后沿同一条直线连续制动到构图位置，末速度为 0，结束时不再硬转向。
- 蓄能阶段出发星球保持完整的大气、海洋和云（第一轮里它们被提前关掉，看起来像变成了低模）。只有在不透明隧道里、系统已经交接之后，才会卸下局部介质。
- 质感：隧道壁是螺旋缠绕的发光等离子体加五步体积介质采样（有真实视差），颜色从深靛经电光蓝过渡到白热核心，少量琥珀色细丝。入口和出口的边缘有噪声扰动，等离子像舌头一样向前涌，而不是几何圆。出口带白热唇边、变形宽银幕式的拉丝光，以及进入真实空间瞬间的曝光抬升。末端光对准当前出口截面。
- 星流拖尾：头部最亮最宽，尾部变细变暗，并略微偏暖，看起来是运动曝光而不是画出来的线。
- 第一人称：跃迁和弦界航道都保留选择时的视角，跃迁中也可以按 V 切换。
- 音效：`warp-spool`、`warp-enter`、`warp-exit`。

**已知问题**：调试入口 `NMS.warpToStar()` 不经过航线预建，目的地在隧道里同步建造，会卡顿约 6–10 s。正常的星图航线会先预建目的地。Hydrogen 在集显 900p 下测得隧道单 Pass 约 9.7 ms，低档位还没有降成本，见剩余项。

## 弦界航道（第二轮完成，待用户实机确认）

原则：门里看到的每个像素，都由穿过后渲染你的那条管线来画。

- **对面**：[portal-view.js](../src/portal/portal-view.js) 是第二个 `GameLegacyPipeline` 实例，选项与主视图相同（不含旧体积云栈），只保留不透明世界、大气和云，关掉船、TAA、泛光、色调映射、调色和 SMAA。它从映射后的相机渲染线性 HDR，由主视图统一做显示变换。两个视图共享按天体缓存的大气传输 LUT。
- **合成**：[portal-composite-pass.js](../src/portal/portal-composite-pass.js) 在云之后、过渡通道之前，逐像素做视线与门面求交，再加对数深度遮挡。没有门网格，所以近平面切过门面时不会穿帮，穿越就是分界线扫过屏幕。接缝是空间折叠：门外这一侧的光被弯向边界，门内向边缘轻微放大并带色散；一道细的白热能量丝分段沿边界流动，其余部分只靠弯折的光标出边界。
- **几何与节奏**：[space-portal.js](../src/portal/space-portal.js) 负责源帧和目标帧、映射（位置、朝向、速度原样带过折叠）、穿越判定（线段与门面求交，任意速度都能穿过）、开合节奏（先画出一条横向接缝，蓄力后纵向撕开并略微过冲；关闭时先缩回接缝再愈合）。
- **穿越**：映射相机姿态和上一帧位置；采用目的系统；出发系统保留为可绘制的"背面"，闭合中的门里显示它；两个视图交换云的时域重建状态（`LiteCloudPass.exchangeTemporalState`），云不需要重新收敛。
- **手感**（11-17 用户反馈"出来后像在平移"）：门打开后不再锁速 145/76 m/s，也不再强制拉中心、自动转船头。只在门前保留轻微的横向牵引，帮你对准。实测穿越前后速度方向与船头对齐度都在 0.98–1.0。
- **光照**：门打开后，对面恒星的光从门里溢出照到船体，越近越强，所以穿越时船体已经被目的地的光照亮。
- **准备**：选航线时就在准备队列里用新视图从到达姿态画一帧（分配渲染目标、绑定目的介质），不再有旧实现那种直接渲染门户时的同步着色器链接（实测 2.9 s 长帧）。
- **形态可调**：`createPortalProfile` 可设置尺寸、四阶谐波轮廓、接缝宽度和亮度、透镜强度和范围、开合时长、接缝占比、单向或双向、一次性或常驻。`doorPortalProfile()` 是单人门的预设。
- 删除：旧的 `spatial-rift*.js`、`RiftDistortionShader`、管线里的 `rift` 通道、离屏门户直绘路径及其所有权测试。新契约测试见 `tools/portaltest.js`。
