# 深空 优化路线图

> ⚠️ 重要说明:本文档记录基于用户痛点整理的全面优化方案。核心原则:**以 WebGPU 为唯一基准全面重构,接受宇宙锁重做**。所有新着色器/材质/后处理一律用 TSL/NodeMaterial 编写,不再写 GLSL。既然母星要单星、半径要放大、noise/height 要改,锁一定会失效,那就放开手按子系统全面优化,最后一次性 re-curation,不被"不破坏锁"束缚。

**最终目标:WebGPU 完美运行,视觉质量全面提升,WebGL2 作为兜底但不追求像素等价。**

> **2026-07-27 用户补充的执行原则**:本轮已经明确接受宇宙锁失效,因此不能把“只做最小修复”当优点。只要不提前侵入后续批次 B/C/D/E 的所有权,A 内与地形、海面、行星视觉尺度、海洋世界多样性直接相关的高质量扩展都应主动发散并落地;**可验证的自由发挥越多越好**。数值契约和自动截图只负责防回归,不能代替用户对真实玩家画面的验收。

> **2026-07-28 玩家实机验收结论**:撤销 A、B 的“已完成”状态。自动合同、固定夹具和隔离截图只能证明代码路径存在,不能替代连续轨道下降的最终画面。实机在约 136.7 km 与 52.2 km 明确暴露:轨道地形多边形化、方形 LOD 分块边界、海陆黑线/黑区、平面且无深浅的水、重复水纹和假尾流、云片而非真实体积、卫星阴影错误置顶、蓝色天空/大气覆盖不透明地形、尚未到云层便整屏突变为蓝色,以及天气/降水缺乏可信完成度。B 视为未完成并从架构层删除重写;A 保留已确认的尺度和内容合同,但视觉部分重新验收。

## 当前 WebGPU 迁移状态（基线 c4e1f0d）

WebGPU 路径能启动渲染、不黑屏,但“迁移已完成约 90%”只是代码覆盖率判断,不能代表视觉完成度。2026-07-28 实机验收证明体积层、深度合成、地形/海面 LOD 仍有架构级错误。以下问题必须以最终连续画面重新验收:

| 遗留问题 | 根因 | 由哪个重构批次解决 |
|---|---|---|
| 大气/天空错误覆盖地形 | 当前深度读取或坐标重建并未产生正确遮挡;52.2 km 实机仍出现蓝色幕布压在地形前 | 批次 B:删除现有体积合成并重写深度所有权 |

| 后处理与体积层顺序/所有权错误 | 体积层表现为屏幕覆盖,说明仅调整 pass 顺序不足以解决空间重建 | 批次 B:明确 world/depth/volume/foreground 单一所有权 |

## 一、宇宙锁影响边界

### 1.1 锁的核心契约

`worlds/milky-way.lock.json` 由 `tools/canonical-world.js:199 buildCanonicalWorldLock()` 生成,记录:
- `identity` / `generatorVersions` / `authoredConfig` / `finiteCatalog`(1024 系统 + 内层指纹)
- `homeSystem`(母星完整档案:stars/binaryOrbit/bodies 全字段)
- `specialDestinations` / `civilizationSites` / `nearbySystems` / `neighborhoodProfile`
- `homeSurfaceSentinels`:`naturalSeaLevel`/`tunedSeaLevel`/`cloudCoverage`/`hasRing`/`mountMaskLo` + 4 方向 `heightSamples`
- 顶层 `fingerprintSha256`(SHA-256 覆盖以上所有字段,`JSON.stringify` 对键顺序和浮点位级敏感)

`npm test` 用 `assert.deepStrictEqual` 位级比对。任何字段(包括两层指纹)的位级差异都会触发失败。

#### 现状与推测根因(仅供参考,待验证)

- **LOD 机制**:`src/quadtree.js` cube-sphere 四叉树,`SPLIT=4.0/MERGE=5.2` 固定距离阈值,**不考虑地形粗糙度**(推测:粗糙山脊远距分裂不足 → 太空看像低多边形)。
- **太空丑推测根因**:~~飞行模式下 `orbitLevelCap=1-2`(`src/planet.js:215`),level 1-2 的 chunk 在 24×24 网格上采样,maxFreq 被压到很低,台地/峡谷等中频细节不参与。没有独立轨道 impostor。~~
  **→ 已推翻(验证 2026-07-27)**:高度场在 orbit cap(level 2)已保留全细节 sd 的 **102.0%**,与全细节场的 Pearson 相关系数 **r = 0.9989**;level 2 与 level 3 的硬件截图肉眼几乎无差别(仅 FPS 97 → 184)。提高 LOD 上限**不可能**修好太空视图。
  **→ 新根因 A(验证 2026-07-27):起伏/半径比过大**。母星 R = 286.0 km,高度场实测 **[−5154, +13447] m**,峰谷差 18.6 km → **relief/R = 6.50%**(3 万采样时 6.38%,6 万采样时 6.50%,取后者),是地球(0.311%)的 **20.9×**、火星的 7.6×、月球的 5.7×,与灶神星(不成球的小行星,8.57%)同级。另注:`hAmp` 名义 8607 m,但最高点 13447 m 已**超出 hAmp 56%**,说明 `hAmp` 不是真实幅度上界。在 1.72 R 距离、1080p/60° FOV 下,天际线偏离正圆 **峰峰值 35.7 px / sd 4.8 px**(占视直径 3.1%);同构图下地球只有 2.5 px。**行星在任何 LOD 下都是一颗"捏皱的土豆",而非行星。** 且因起伏能量集中在低频(见 r = 0.9989),加细节无法改善,只能改 hAmp/R 比例。
  **→ 曾提出的"新根因 B:轨道 skirt 过大"已自我推翻(2026-07-27,同日)**:`skirtDrop = R·cellAngle·2.5 + 6` 在 level 2 = **4393 m**(hAmp 的 51%)确实很大,但 **skirt 在几何上不可能造成锯齿轮廓**——裙边顶点位于 `len − skirtDrop`,永远比源顶点更靠近球心,只能填补背后的裂缝,**无法向外扩张剪影**。这是构造性证明,不是推测。同时实测级间高度差(6000 方向)显示 level 1/2/3 的 skirt 只有该级最大邻接高差的 **2.8× / 1.5× / 1.7×**,在轨道级别是合理量级。
  **→ 轮廓线锯齿 100% 来自高度场本身**(relief/R = 6.50%,直接由 `height()` 测得 ±18 px 摆动,与渲染管线无关),即新根因 A 是唯一根因。
  **→ skirt 仍有独立的次要问题(非本痛点)**:在近地级别严重过尺寸——level 4 的 skirt 1103 m 是该级最大邻接高差(49 m)的 **22.5×**,level 6 是 14×。这浪费几何、膨胀 chunk 包围球,并可能在掠射角从山丘背后露出。按实测高差重算尺寸,作为质量/性能项处理。
- **太空看海洋远看效果假(新增痛点)**:~~推测根因是海面 LOD 与地形 LOD 共享 quadtree 但海面材质在远距离无细节 contribution,且 WebGPU 的 `applyWaterWaves` TSL 实现在低 LOD 下退化为纯色。~~
  **→ 修正为定量确认(验证 2026-07-27)**:与 LOD **无关**,是吸收模型饱和。见 2.3 的完整数据。
- **山脊锯齿推测根因**:~~`src/noise.js` Simplex 用固定 12 梯度向量(GRAD 数组),球面采样某些方向可能有 bias,`ridged` 的 `1-|n|` 平方可能放大 bias → 锯齿脊(`src/planet.js:299-303`)。~~
  **→ 已推翻(验证 2026-07-27)**:把梯度表从 12 扩到 24/48/96(Fibonacci 球面梯度,|g| = √2,置换表不变)后,`ridged()` 场的梯度方向直方图 spread 只从 **12.9% 降到 11.6%**,唯一非平凡谐波 c2/c0 从 1.50% 降到 0.84%。方向性 bias 在数值上可忽略,不是锯齿来源。
  **→ 同时推翻候选修法**:把 `1-|n|` 换成 smooth-abs(`√(n²+s²)−s`,再按 `1/(1−s)` 归一)后,中点插值误差**完全不变**(level 2:0.0638 / 0.0638 / 0.0639,s = 0/0.03/0.10)。C0 折痕不是锯齿成因。
  **→ 新根因(验证 2026-07-27):八度硬门限 `if (o > 0 && f > maxFreq) break;`**(`src/noise.js:91,109,130,147`)。沿 maxFreq 连续对数扫描(900 步)显示高度在门限处**阶跃**:最坏单步 rms Δh **217.9 m**(hAmp 的 2.53%),单点 max Δh 达 **2351.5 m**,且跳变集中在 f ≈ 24.3 与 f ≈ 55.8——正好落在 LOD 级别边界(16.3/32.6/65.2/130.4…)上。
- **地形散乱推测根因**:~~`src/planet.js:285` `belt = smoothstep(...)` 省份掩码是硬 smoothstep,边界是等值线;山只在 belt 区出现,belt 边界可能是山的硬边。~~
  **→ 已推翻(验证 2026-07-27)**:沿大圆测 belt 的 5%→95% 过渡带宽度为 **中位 64.1 km / 均值 79.8 km / 最窄 41.3 km**(母星周长仅 1797 km),53.1% 的球面处在过渡带内——这是**极软**的过渡,不存在等值线硬边。
  **→ 同时推翻"陆块破碎"的直觉**:连通域分析(720×360 等距网格,经度环绕)显示陆地占 44.8%,共 715 个连通陆块,但**最大陆块占陆地 42.9%、前 3 占 72.3%、前 8 占 87.4%**,687 个碎屑加起来只占 5.6%。与地球(最大陆块 ~57%、七大洲 ~94%)是同一量级的分布,**陆块本身是连贯的**。
  **→ 新根因(验证 2026-07-27):山脉呈孤岛分布**。`mMask` 门限 `> 0.002` 把 **61.7% 的球面**完全排除在山脉之外,而 belt 项 `(0.12 + 0.88·belt)` 单独就让山脉振幅摆动 **8.3×**(1388 m ↔ 11563 m)。山不是沿边界硬切,而是零星孤立地"长在几块地方",中间大片是无特征平地——视觉上读作"散乱"。
- **几何边缘推测根因**:推测是 noise 本身问题(非 LOD 接缝,skirt 已遮挡),但需验证是否还有其他因素(如 morph target 偏差、maxFreq 跳变)。
  **→ 部分确认(验证 2026-07-27)**:maxFreq 跳变确实存在且量级很大(见上,max Δh 2351.5 m);skirt 不但没"遮挡"问题,自己就是问题(新根因 B)。

#### 优化方向(候选,根因验证后由执行者定方案)

**目标**:太空俯瞰与地表形态一致无方块感;LOD 切换不可见;山脊连续非锯齿;地形板块连贯无散乱硬边;太空看海洋有真实感(深度变化/Fresnel/远近视差)。

**约束**:噪声/height 算法改动破坏锁(走 re-curation);LOD 调度参数、轨道视图方案不破坏锁。

**可选思路**(执行者自由选择,不限于以下;根因验证后可能完全换方向):
- ~~噪声方向性 bias:fable5 的噪声烘焙思路(GRAD 扩展、多频段 ridged、domain warp)~~ — GRAD 扩展经 A/B 证伪
- ~~地形省份边界软化:fable5 的 ecotone warp(指状交错而非等值线)~~ — 边界本就 64 km 宽,经证伪
- ~~LOD 粗糙度感知分裂:fable5 的 errBoost(粗糙区域提前分裂)~~ — level 2 已 r = 0.9989,无采样不足
- ~~太空视图:独立轨道 impostor~~ — 细节充足,impostor 不解决形状问题
- ~~海面 LOD:球面 impostor + 距离相关 Fresnel~~ — 与 LOD 无关,是吸收饱和
- 保留 `height(dir, maxFreq)` 单权威函数契约(AGENTS.md 要求),只在其上层加分类场

**实际执行(2026-07-27 根因验证后重定方向)**:上述 5 条候选全部被自建诊断工具的 A/B 数据证伪,改为以下 4 条,全部直指已验证根因:

1. **压缩 relief/R 比例**(对应新根因 A,`hAmp` 或 `R`)。目标把 6.50% 降到 ~1.5–2.5%(火星/月球量级),让轮廓线读作行星而非小行星。与 2.5「母星半径 → 700–1000 km」天然协同:R 286 → 900 km 且 hAmp 不变即得 2.03%,一处改动同时满足两个批次的验收。**破坏锁,走 re-curation。**
2. **重算 skirt 尺寸**(次要项,**非**剪影修复)。`skirtDrop = R·cellAngle·2.5 + 6` 与实际需求脱钩:轨道级 1.5–2.8× 最大邻接高差(合理),近地级 **22.5×**(浪费)。改为按 chunk 自身局部起伏定尺(chunk 已在采样自己的高度,取 max−min 即得),既贴合需求又自适应——平坦洋底 chunk 得到极小裙边,山区 chunk 得到足够裙边。**不破坏锁**(纯几何)。
3. **八度连续淡入且不污染反馈链**(对应山脊锯齿新根因)。`fbm`/`fbmEroded` 直接同步淡入 contribution/norm;`ridged` 也同步淡入 contribution/norm,但始终用完整八度信号更新 `weight`,避免把半淡入值反馈到所有后续八度而产生 62.5% 恶化。**破坏锁,走 re-curation。**
4. **软化山脉孤岛分布**(对应地形散乱新根因)。降低 `mMask > 0.002` 门限排除的 61.7% 球面占比,并压缩 belt 项 8.3× 的振幅摆动(如把 `0.12 + 0.88·belt` 抬底到 `0.35 + 0.65·belt`),让山脉成脉络而非孤岛。**破坏锁,走 re-curation。**

#### 实施结果（2026-07-27）

- `src/world-config.js` 将母星渲染半径定为 **900 km**,月球轨道同步调至 **3200 km**;星系实例在创建 `BodyFrame` 前消费 tuning,轨道周期按 `r^(3/2)` 同步缩放。母星实测 relief/R 从 **6.50% 降至 2.03%**,同构图轮廓峰峰摆动从 **35.7 px 降至 11.3 px**。
- `src/noise.js` 新增连续 `frequencyBlend`,四类分形噪声均跨一个倍频程连续引入八度;`ridged` 保持完整 weight 反馈链,仅同步淡入 contribution/norm。完整 `height()` 连续扫描最坏单步 rms 从 **217.9 m 降至 13.6 m**。
- `src/planet.js` 将山脉 mask 改为连续 foothill 基底 + `0.34 + 0.66·belt`,有效无山区域从 **61.7% 降至 35.4%**,振幅摆动从 **8.3× 压至 2.9×**;前 8 大陆块占全部陆地 **93%**。
- `src/quadtree.js` 用 chunk 实测父子径向差计算 skirt,不再按 cellAngle 生成近地千米级裙边;`tools/stageatest.js` 固化半径、LOD 连续性、山脉连续性与 skirt 契约。
- 用户图中的黑色描边被进一步拆成两个独立根因:地形高 LOD 的深裙边会透过浅水/太空轮廓成为黑墙;水面混合 LOD 的球面弦缝也会形成暗线。现在地形仅在宽广轨道层保留裙边,level ≥ 3 由 geomorph 共边；水面使用 **0.05 m** 数值封口,近岸由 **3.5 m 动态涌浪覆盖**接管。`tools/stageacoastdiag.js` 在原 2048×1200、70 m 构图中可独立切换 terrain/water/skirts；固定 WebGPU 岸景最终以白色破碎浪带取代黑色轮廓。
- 运行时地形几何停止在母星约 **2.7 m** 网格；最后的亚米级权威噪声仍用于碰撞和材质微细节。旧方案在 70 m 高度为不可见的亚像素起伏持续排队上百块,既不能改善地面观感,又把复核帧拖入半构建状态。

- WebGPU 固定场景证据:`test-results/stage-a/orbit.png`;数值证据:`tools/terrainnoisediag.js` PROBE 2/4/7/8/9;全类型地形与 morph 回归:`npm run test:terrain`。

#### 新增 A 痛点:半径数值变大,视觉仍显小

- **代码事实**:`world-config.js` 的 900000 m tuning 已被 `galaxy.js` 在创建 `BodyFrame` 前消费,运行时 `planet.R = 900000`,月球 `orbit.renderRadius = 3200000`;这不是只写在文档里的计划。
- **此前验收缺陷**:轨道测试和若干传送/到达逻辑使用 `R × factor` 定义相机距离,当半径和距离一起同比放大时,屏幕角直径几乎不变。因此“R 已从 286 km 改成 900 km”**不能推出“玩家视觉上更大”**。
- **A 所有权**:实际轨道/接近过程的相机距离、FOV、LOD 读形、下降速度与地表曲率尺度;需要用同一分辨率下的屏幕直径、接近时间和地形可读性共同验收,不能只断言半径字段。
- **B 后续必须考虑**:大气壳厚度、云层轮廓与辉光会改变星球视觉边界和尺度感。A 不提前重写散射/体积云,但 B 的验收必须包含“不能用过厚辉光把 900 km 星球再次视觉缩小”。

#### A 继续扩展（锁已破坏,不做最小修复）

- 地形/海面使用一致的屏幕误差与岸线共边策略,专门消除太空和近岸黑色描边。
- 为海面补充近场毛细波、中尺度风浪、远场统计法线/白沫三个频段,而不是只靠三条低频正弦。

### 2.2 光照与大气（深度重写）

**[进行中 2026-07-29] 阶段:删除现有深度/体积合成并重新设计；GPU 资源所有权与连续镜头复验**

#### 现状与推测根因(仅供参考,待验证)

- **光照不够细腻(原推测)**:`src/galaxy.js` 的恒星光未保留完整色温,伴星还会在地平线下继续以 PointLight 照亮地表。
  **→ 已确认根因(2026-07-28)**:问题不是单纯缺 HDRI,而是恒星辐射没有统一的数据模型——颜色、距离衰减、地平线门控和 shader 输入各走各路。现已用黑体色温 + 逆平方辐照度生成至多双星的统一 field,Directional/Point、地形、水面、云和大气共用同一组方向/颜色/强度,每颗星独立做地平线门控。
- **日落不美(原推测)**:`src/atmosphere-webgl.js` 使用经验色混合和较弱多次散射。
  **→ 发现更严重的 WebGPU 根因(2026-07-28)**:初版 Node 大气曾把归一化 RGB 当作 `/m` 消光系数,再乘米级步长,导致积分几乎瞬间饱和为不透明黑/灰幕。现改为真实数量级的 Rayleigh 系数 `5.78e-6 / 13.56e-6 / 33.10e-6 m⁻¹`、Mie 标高约 1.2 km、Rayleigh 标高约 8 km,由长光程自然产生红橙日落;有界多次散射只补能量,不再糊成发光壳。
- **背阳面黑(原推测)**:`ambient`/`hemi` 太低且无间接光。
  **→ 已确认(2026-07-28)**:确有夜侧间接光缺口,同时伴星地平线下漏光会掩盖真实问题。修正门控后加入仅在太空/夜侧生效的微弱星光与天光填充,硬件夹具测得直射近零但行星平均亮度 8.1、非全黑,不会洗白昼面或近地表。
- **双星 sunDir 只取主星(原事实)**:伴星不进入大气、云和水体。
  **→ 已修复(2026-07-28)**:`stellar-radiometry.js` 生成多星场;大气散射、云照明、水面 glint 与场景灯均逐星累加,测试夹具确认两颗恒星贡献均非零。
- **旧大气比例/星球看小**:A 已将母星半径定为 **900 km**、月球轨道同步为 **3200 km**。B 没有再次改动内容尺度,而是把可见大气压回物理上合理的约 **120 km** 渲染包络,内部仍按 8 km/1.2 km 标高积分,避免厚重发光壳反过来把星球视觉缩小。体积云和薄大气现在强化球体尺度而非遮蔽它。
- **后处理与深度(新增已确认根因)**:生产 Node 链此前没有把主场景 depth 交给大气/体积云,且 volume pass 位于 warp/rift 之后,会让云雾像贴在屏幕上并穿过地形。现由主 MRT 暴露深度,大气/云在同一深度空间提前合成,再进入 warp/rift；8-tap sun shaft 也使用同一遮挡与太阳可见性。
- **开始页到接管的 15–20 FPS/近冻结(2026-07-29 实机根因)**:2560×1440、Ultra、RTX 5080 Laptop 的真实 WebGPU trace 证明当时 `cloudEngage=0`、体积云 mesh 未渲染,低帧率不能归因于“电影级云太贵”。点击前后集中发生约 **386–392** 次 shader/pipeline 事件和 **164–189** 次 GPU texture 创建；地形/水体每个 chunk 的 native morph position/normal 被上传为独立 `rgba32float` 纹理,飞船前景层又未被普通 scene camera 预热。3.2 ms chunk 预算只限制 CPU 顶点计算,完全没有限制随后发生的 GPU 激活。
- **大气随镜头闪烁(2026-07-29 已复现架构错误)**:首轮 trace 捕获到同一 `output` texture 在一个 WebGPU synchronization scope 中同时作为 TextureBinding 与 RenderAttachment,命令缓冲随即 invalid。诱因是异步管线编译、体积 RTT 改尺寸和实时 RenderPipeline 并发；这不是能靠降低采样数遮住的“噪声”。修复要求启动期一次构造正确像素预算、串行化 compile/resize/render,并以连续转镜诊断确认不再发生。

### 2.3 水体与沙滩（含海面 LOD）

**[进行中 2026-07-28] 阶段:海岸、水深、波谱与近水交互重新设计**

> **目视复核失败证据**:70 m 近岸截图中,海水仍是大块平滑青色,深湖视觉像浅水,可见波浪不足;水陆边界是一条黑线而非湿沙—浪花—浅滩—深水连续过渡。此前 absorption sd、位移幅度和 uniform 联动通过,只说明数学路径存在,**不说明最终画面写实**。

#### 现状与推测根因(仅供参考,待验证)

- **平面感(事实)**:`src/planet.js:706` 水球壳顶点高度恒 0,`src/shaders-webgl.js:474-481` 只有法线扰动无顶点位移。
- **无真反射(事实)**:`src/shaders-webgl.js:470-472` 菲涅尔只是颜色 mix 到固定 `uSkyC`(构造时一次性固定,不随日落变化)。

- **太空看海洋远看效果假(新增痛点)**:WebGPU 路径下太空看海洋远看是一片完全一样的劣质蓝色,无波纹/深度变化。~~与 2.1 海面 LOD 联合解决。~~

  - 海洋覆盖球面 **54.5%**,水深中位数 **936 m**。

**实际执行(2026-07-27 根因验证后补充优先级)**:上述思路全部保留,但**顺序被验证数据强制**——`absorption` 饱和(sd 0.0722)必须**第一个**修,否则位移/反射/泡沫全部被同一片恒定蓝色淹没,做了也看不见。落地顺序:

1. **分波长 Beer–Lambert 吸收**(替换单标量 `1 − exp(−0.05·d)`)。RGB 三通道各自消光系数,红光衰减快、蓝光衰减慢,自然产出浅绿松石→深靛蓝的连续梯度。目标 absorption sd ≥ 0.25。**不破坏锁**(纯 shader)。
2. **海面真位移**(Gerstner 波,球壳切空间;当前 ±0.47 m → 近岸 ≥ ±1.5 m)。**不破坏锁**。
3. 距离相关 Fresnel / sunDir 接通死代码 / 湿润带 + 泡沫 / 云阴影 / 飞船交互 —— 按原候选思路推进。

### 2.4 植被与材质（植物系统完全重做）

> ⚠️ **重做决定(用户明确指示)**:现有地表植物系统(树、草、外星植物、远景 proxy tree)全部禁用并完全重做,**没有"优化现有实现"的说法了**。
>
> **禁用范围**:`src/scatter.js`(近地表:树/草/外星植物/灌木/pod)和 `src/farflora.js`(远景 proxy tree)的 `setPlanet` 直接 return,不创建任何 InstancedMesh。`src/flora-system.js`(V2 风摆/距离溶解)和 `src/shaders-node.js` 的 `applyWindSway` 代码保留供参考,但不再被调用。
>
> **重做原因(根因已确认,非推测)**:TSL/NodeMaterial 的 `positionLocal` 节点**不包含 instanceMatrix 变换**,导致:
> - 风摆 phase 无法基于实例位置 → 所有植物同步摆动(地震感)
> - 距离溶解用 `positionLocal.sub(uCamL)` 算距离 → 所有实例同步位移(石头也跟着抖)
> - `GROW.value`/`uAltK` 每帧变化 → 顶点偏移幅度每帧变化(幅度抖动)
> - `MeshStandardNodeMaterial` 构造未传 `emissive`/`emissiveIntensity`,`vertexColors` 时未设 `emissiveNode` → 发光植物丢失
>
> 这是 TSL 节点图的架构性限制,修补无效。必须重做时从架构层面解决:要么用 `instanceMatrix` 节点显式访问实例矩阵(若 TSL 支持),要么改用 CPU 端预计算每个实例的 phase/anchor 并作为 `InstancedBufferAttribute` 传入,shader 只做插值。
>
> **重做范围**:不止是树,全部植物都要重做——树、草、外星植物(weird/slime biome 的 pod/blob/crystal 草本)、灌木、pod 发光植物。岩石(rock/boulder/crystal 矿物)不在重做范围,但 scatter.js 现已一并禁用,重做植物时一并恢复矿物渲染。

## 四、re-curation 流程

### 4.1 触发条件

### 4.2 完整步骤

参考 `package.json:28-30` 三个脚本:

1. **候选生成与打分**:`npm run world:curate`
   - `tools/curate-finite-galaxies.js` 枚举 MILKY-001 到 MILKY-256,对每个 seed 调用 `buildGalaxyCatalog` + `generateSystemSpec` + `buildCivilizationSites`,计算 `visualScore`
   - 输出 `worlds/finite-candidates.json`,列出 top12 / top4
   - 成本:纯 Node 计算 256 个 seed,几十秒到几分钟

2. **截图人工评审**:`SEEDS=MILKY-038,... npm run world:curate:shots`
   - `tools/capture-world-candidates.js` 启动本地 server + Playwright,对每个 seed 截图 spawn、各类型行星轨道、低空飞行、地表、飞船
   - 输出到 `test-results/world-candidates/{seed}/`
   - 成本:每 seed ~1-2 分钟浏览器时间

3. **更新 `src/world-config.js`**:把 `WORLD_CONFIG.galaxies['milky-way'].seed` 改成选中的 seed

4. **生成新锁**:`npm run world:lock`
   - `tools/export-galaxy-catalog.js` 写 `worlds/milky-way.catalog.json`
   - `tools/export-canonical-world.js` 调 `buildCanonicalWorldLock()` 写 `worlds/milky-way.lock.json`

5. **验证**:
   - `npm test`(纯 Node 合约检查,~3s)
   - `npm run test:smoke`(一次浏览器启动,~1min)
   - `npm run test:full`(全套浏览器套件)
   - 视觉验证:`docs/curation/finite-worlds-v2/{seed}/` 固定相机捕获
   - multiplayer/save 迁移评审(AGENTS.md 要求)

## 六、风险与注意事项

1. **fable5 算法适配**:fable5 大量依赖 compute shader、StorageTexture、StorageBuffer、atomicAdd,WebGPU TSL 路径也不完全支持。算法层借鉴,代码用 TSL/NodeMaterial 重写。最痛的是 Scatter 的 atomic append——必须改成 CPU 端 JS 散布(深空 scatter.js 已是这个模式)。

2. **cube-sphere 适配**:fable5 的 2D world xz → uv 纹理采样在球面上不工作。深空必须用顶点预计算 varying 或 render-to-texture 球面投影。FFT 水面需切空间坐标适配。

3. **height() 单函数约束**:深空 AGENTS.md 强调 `height(dir, maxFreq)` 是单权威函数,各级 LOD 共享。**不要**改成 heightfield 纹理架构,保持 height() 函数,只在其上层加分类场(顶点预计算)。

4. **球壳 FFT 性能**:只在玩家当前进入的星球启用 FFT,其他用静态法线扰动。多个星球同时跑 FFT 不可行(1024 星系)。

5. **草密度性能**:InstancedMesh draw call 不变,但 instance 上传带宽是瓶颈。用 DynamicDrawUsage + staging buffer 增量更新;LOD 远距不画草;chunking + frustum culling。

6. **IQ 2013 许可证**:绝对不能抄,代码、变量名、算法结构都不能出现在深空里。

7. **re-curation 时机**:所有破坏锁的改动完成后一次性 re-curation,不要中途多次 re-curation(每次都要重新筛选+评审+验证,成本高)。

8. **测试纪律**:每次子系统改动后 `npm test`(~3s);大改后 `npm run test:smoke`(~1min);PR/发布前 `npm run test:full` + 针对性 browser test;视觉改动 `npm run shots` 截图对比。
