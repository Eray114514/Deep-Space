# 云与星球观感：反馈、参考审查与返工决定

日期：2026-09-30。审查生产版本：`8130a25`。本轮只审查、修订计划与验收，不修改运行时代码。进度仍以[批次 B](../cloud-atmosphere-rewrite.md)为准，执行按[阶段 4 返工顺序](../cloud-phase4-volume-march.md#返工执行顺序)，验收按[视觉协议](../visual-targets/README.md)。

## 用户反馈与审查结论

用户先指出代理自行截取的昼/夜整球图存在大面积白色尖刺；尖刺修复后，继续明确反馈：即使不再有那个 bug，星球仍不像从宇宙中观看的写实星球，云也不自然；与星际公民或一般写实目标相比，整体质量不对。用户要求记录这次反馈及结论，避免再次错误验收，并充分参考早已提供的本地项目和新增 three-geospatial。

**当前画面视觉未通过。** “尖刺已修复”仅关闭相应几何缺陷，不代表云已经合格，也不代表整个画面已无 bug。此次复看的是修复后的[昼侧原图](../baselines/b4-cloud-geometry-2026-09-27/p0-day-S4-globe.png)与[夜侧原图](../baselines/b4-cloud-geometry-2026-09-27/p0-night-S4-globe.png)。更早带尖刺的[矩阵](../baselines/b4-local-2026-09-27/README.md)保留为漏检坏例，不能拿它证明正常玩家链通过。

| 已观察到的问题 | 判断边界与后续归因 |
|---|---|
| 昼侧大片灰白覆盖近似涂层，内部亮暗与厚薄层次不足 | 整体写实目标失败；需分别检查云密度、光照、空气和曝光贡献，不能仅凭图断言单一着色器根因 |
| 云区边缘出现明显块状、条带和规则断裂，整球天气尺度不自然 | 要对照天气 atlas、密度场、远云表示、长切线采样及重建；不能直接认定全是纹理分辨率问题 |
| 夜侧亮区及晨昏交界仍读作片状覆盖，地表—云—空气缺少可信层次 | 需要侧光及不同高度对照；夜半球本来可以很暗，不能以整体提亮修正 |
| 圆球的云、地表和临边没有形成可信的整体 | B4 先解决云与现有大气/地表的关系；地表材质、方向性水面反射和显示链若仍限制画面，分别归因给 A/B6/R，不能宣称全靠云就能达到最终目标 |

结论是**既有后续未完成的工作，也有现有实现需要返工的部分**。不能用“B4 尚未完成”解释一切后继续沿原参数扩云种，也没有证据要求推翻全部工程基础。

保留坐标/绝对时间/米制单位、唯一天气输入、已验证的深度与联合介质传输，以及有坏例控制的回归。首族的天气到密度映射、真实特征尺度、采样与自阴影/云内散射需要联合重做或校准。现有代码中的短太阳 march、无误差界长路径截断等已由[局地高度诊断](b4-local-height-2026-09-27.md)定位为限制，但各自对这些画面的贡献还需受控 A/B。

B5 已关闭的是记录过范围的传输/照明契约，**不是最终星球观感的质量担保**。若隔离实验发现空气源项、天空照明或合成仍有缺陷，应按证据重开受影响项并复验，不能因为曾经勾选完成就排除它。统一 TAA 属于 B7，也不能指望它修复错误的静态云形。

此前代理对正常玩家画面检查不足，漏掉明显尖刺；工程断言、取证数量和完整报告被赋予了过高权重。修正办法是实行视觉否决、逐项原图审查与连续过程审查，具体规则已写入唯一[视觉协议](../visual-targets/README.md#执行门槛与否决规则)，而不是再增加一句“注意画质”。

## three-geospatial：值得作为主要工程参考

[用户提供的云演示](https://takram-design-engineering.github.io/three-geospatial/?path=/story/clouds-clouds--basic)及[上游仓库](https://github.com/takram-design-engineering/three-geospatial)。本轮浏览器实际查看了 Basic 的默认近地视角，能看到云团明暗、云区孔隙、远近空气透视与地平线融合；这对当前目标有参考价值。**没有据此验收其整球、完整升降、多星或本项目性能。** 本轮对其余模块的判断来自源码与 README，不冒称已逐个运行所有演示。

源码审查固定到 `b012ad06d858fc035d88aacfd73f092f93c994e4`；该版 clouds 为 0.7.6、atmosphere 为 0.19.1。上游 README 明示 API 尚不稳定，且正在向 WebGPU/TSL 改造；这里研究的是该提交现存的 WebGL 着色器路径，不改变本项目 WebGL2/GLSL 决策。根许可为 MIT，实际移植仍须保留通知、核对具体文件及纹理/外部资源来源。

可复查的固定版本入口：[云源码](https://github.com/takram-design-engineering/three-geospatial/tree/b012ad06d858fc035d88aacfd73f092f93c994e4/packages/clouds/src)、[大气照明适用范围](https://github.com/takram-design-engineering/three-geospatial/blob/b012ad06d858fc035d88aacfd73f092f93c994e4/packages/atmosphere/README.md)、[整体 API 状态](https://github.com/takram-design-engineering/three-geospatial/blob/b012ad06d858fc035d88aacfd73f092f93c994e4/README.md)。本机研究副本在忽略目录中，不作为交付依赖。

| 范围 | 值得参考的具体内容 | 本项目如何采用、边界 |
|---|---|---|
| clouds：天气与密度 | `shaders/clouds.glsl` 中 `sampleWeather`、`sampleMedia`：覆盖、层高 profile、主体形状与细节侵蚀分离，并考虑细节 LOD | **最高优先级**。用于首族候选及与旧密度同场 A/B；保留本项目局地云底/米制尺度/唯一天气所有者。上游也有尺度 TODO，不整段当物理真值 |
| clouds：云内照明 | `shaders/clouds.frag` 的光学厚度 march、多八度散射近似、近程 march 与 Beer shadow map 配合 | **最高优先级**。比较光照质量和成本；多次散射是近似，要做受控介质和能量检查。不能只抄少量太阳步数却省略其余阴影机制 |
| atmosphere：空气与场景照明 | 预计算散射、太阳/天空照明及 aerial perspective 的接口和组织 | **高优先级对照**。检查当前云/空气融合和地表入射光；不直接替换 B5。其大场景后处理照明是 Lambertian 路径，标准材质灯光路径有局地近似，不能直接套到我们的 PBR 海面/地形/船体 |
| core：大尺度坐标 | 椭球、地理坐标/ECEF、相机和原点变换等基础 | **选择性参考**精度与边界处理。我们的天体坐标、球体及宇宙内容仍归现有模块，不引入地球 GIS 数据模型作为游戏世界 |
| clouds：时域与重建 | `CloudsPass.ts`、`cloudsResolve.frag` 的上一帧变换、速度/深度、历史采样与限幅 | **B7 重点参考**。B4 只预留内容/运动接口，不叠加第二套 history；必须覆盖本项目天气运动、浮动原点、切星和门户 |
| effects 与其他包 | 几何/深度诊断、抖动与后处理组织；镜头效果和地理场景示例 | 诊断方法可复用；镜头光晕、地图/瓦片/地球数据接入优先级低，不能掩盖云形问题，也不因演示漂亮而全库引入 |

建议采用深度是**重要子系统的设计和算法级参考，必要时移植有明确收益的 GLSL 片段**。它支持普通 Three.js，不要求把游戏改为 React；但直接引入整个效果链仍涉及 composer、log depth、云/空气合成、双星、多天体、资源生命周期及资产成本。当前不把整库依赖列为默认路线。只有首族对照证明局部适配明显不如整包试接，才做有边界的兼容性试验，并用同一验收矩阵决定；不能先迁库再等它自然变好。

## 执行决定

返工分为四个连贯成果组：**首族从密度到照明的完整成像 → 首族跨消费者与动态天气 → 扩展云族 → 全矩阵收尾**。每组内包含诊断、实现、原图/动态复核、性能与文档提交，不按参数或测试脚本拆成逐次汇报。具体触点、依赖、停止条件和难度编号见[阶段 4 计划](../cloud-phase4-volume-march.md#返工执行顺序)及[难度表](../remaining-work-difficulty.md#b4先做一族再扩云种)。

本次文档提交只完成反馈与返工方案落库。上述参考尚未因本次研究而进入生产，也不改变 B4 的未完成状态。
