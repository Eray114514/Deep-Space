2. **量化测量确认了一条云的结构性主因，但不是所有闪烁的唯一原因：**步进预算按"渲染壳厚度的百分比"分配，而不是按"被解析对象的尺度"。实测（R=6000 km、相机高度约 147 km、壳 400–14000 m、48 步上限）：0° 时 435 m/步、层云内 3.4 个采样；80° 时 1632 m/步、**层云内只剩 0.9 个采样**；88° 时 8.1 km/步、0.2 个采样。这个低轨机位里透视会让大部分屏幕落在掠射区；S4 远景不能照搬这个面积结论。少于一个样本会造成命中/漏采和缺乏光程积分，结合低分辨率、屏幕相位与步数上限就表现为色块和忽隐忽现。§1.1 分开记录了大气积分、轮廓上采样、云采样和历史污染，禁止再把它们混成一个原因。

## 1. 为什么要重写，而不是继续修

> 完整的前因后果见 **§0"发生了什么"**。本节只保留支撑"重写"结论的核心论证。

上一轮增量修补（见 §0）**用户验证结论：一个问题都没解决**。云仍然发黑、大气仍然闪，且 bug 总量增加了。用户判断："继续改就是等于修补屎山。"这个判断是对的，理由不是情绪化的：

上一轮修了三处真实缺陷（图集 UV 极性不一致、体积 RT 尺寸抖动、大气射线起点抖动），每一处都有测量支撑，但都没有覆盖用户看到的全部现象。对旧云，另一个已确认的结构性错误是：

对旧云而言，已确认的结构性主因之一是：**步进预算按"渲染壳厚度的百分比"而不是按"被解析对象的尺度"来分配。**

实测（R=6000 km，壳 400–14000 m，48 步上限）：

| 视线角 | 射线穿壳长度 | 实际步数 | 步长 | 落在 1500 m 层云里的采样数 |
|---|---|---|---|---|
| 0°（正下方） | 13.6 km | 31 | 435 m | 3.4 |
| 60° | 27.2 km | 48（触顶） | 567 m | 2.6 |
| 70° | 39.8 km | 48（触顶） | 828 m | 1.8 |
| 80° | 78.3 km | 48（触顶） | **1632 m** | **0.9** |
| 88° | 389.7 km | 48（触顶） | 8119 m | 0.2 |

这张表对应约 147 km 的低轨机位；此时透视把屏幕的大部分面积压到掠射区。它不能代表所有 S3/S4 远景机位，但足以证明用户报告的低轨云层在大面积屏幕上欠采样。由此可确认两种直接后果：

- **"一堆白色色块"** —— 单条射线只有约一个密度/光照样本时，没有可靠的体积积分；再叠加低分辨率重建就容易读成平面色块。
- **"云忽有忽无"** —— 采样数 < 1 时，云是否被命中取决于起始相位；即使相位不含 frame 项，屏幕锁定的 hash 在镜头运动时也会换到另一个世界位置，云仍会爬动/闪进闪出。

把 48 提到 64 也救不了：80° 时仍是 1.2 km/步。这不是常数调参能解决的问题，必须换结构（逐射线裁剪到实际占用的高度带 + 空域跳过 + 分层求交）。这就是为什么要重写而不是继续打补丁。

另外，上一轮暴露了一个**必须写进新设计的硬约束**：

> **当时的 WebGPU 生产路径没有有效时域累积。** 重投影只存在于 `volumetric-pass-webgl.js`（WebGL 回退路径），`GameNodePipeline` 当时没有可用 history。上一轮按旧计划实现了"屏幕像素 + 帧序"的时域抖动，seamtest 立刻抓到：**静止相机下 75–138 px 抖动**（基线 0 px）。之后补出的局部累积原型又被连续大幅运动推翻，当前默认禁用；没有有效累积的逐帧抖动就是纯噪声。
> **结论（2026-08-09 修订）：阶段 4 使用确定性中点/分段求积并以单帧质量收敛为先；不把静态屏幕 hash 当默认答案。失败的局部体积累积不再单独返工；阶段 7 统一实现全屏 TAA、运动向量和体积 history，避免两个时域所有者再次互相污染。**

## 2. 用户要求（原文要点，逐条编号，这是验收标准）

总纲：

- **R0** 实现极其真实的大气体积云，**绝对的写实风格**。
- **R1** 性能要优化好，但**画质优先**："先保证效果而不是无限制降画质以换取性能"。写实是前提，不是可协商项。
- **R2** 发挥原生 WebGPU 的能力。
- **R3** 云类必须足够多。不只是多层的不同云类，**单层内也要分很多云种**。
- **R4** "你只能多做不能少做"。这是表现重构，目标是更好；实现方式不限，改什么都行。
- **R5** 不要沿用原来的云和大气实现代码。当成搭建新项目。

四个必须做好的场景：

- **S1 地面向上看。** 两点：(a) 云不是天花板，**每片云高度不一样**；(b) **每个区域的底层云高度也不一样**，要有物理成因导致不同地方的云有差距。
- **S2 穿过云层到上方，云海飞行。**
- **S3 从宇宙看星球的大气云层。** 必须真实。**绝对不能用几片白色不规则色块敷衍。** 要"真正的太空看地球的那种云效果"：云是**有体系的**，有的地方没有云、有的地方有云，而不是每个地方一样的覆盖率。**太空看云的性能必须做好**，否则视野里一堆云会很卡。参考目标：**星际公民（Star Citizen）的大气云层**。
  > 参考图：`docs/visual-targets/星际公民_目标比对/星际公民_太空云层.jpeg`，与同目录 S2/S4 目标一起使用；`orbital-clouds-reference.png` 是旧基线，不作为最终验收图。
- **S4 完全到达太空**，视野能看到整个星球球体与大气云层。

一致性与分层要求：

- **C1 一致性：** 太空看到某地没有云，飞过去也必须没有云。
- **C2 不做无效流程：** 允许存在"几乎没有云"的层，但这些层**不要做得过厚**——"我不能上升半天却看不到大气任何变化"。空层要短。
- **C3 地面到第一层云可以稍微高一点**，云太低体感不好。
- **C4 云千万不能同质化。就算同种云也不是一定在同一高度。**
- **C5 云量的定义：** 一个星球的云量**不是单个区域的云覆盖率，而是从太空看的整体覆盖率**。覆盖率 50% **不等于**近地区域规则地"满一格空一格"；50% 意味着**从太空看大约一半的地方没有云遮挡**。

> **C5 是最容易被实现错的一条，也是"白色色块"观感的另一半成因。** 旧实现把覆盖率当成每个局部的密度目标，于是处处都是半满，从太空看就是均匀的花斑。正确做法：覆盖率是**面积占比契约**，由天气系统（气旋、锋面、副高晴空区）在**行星尺度**上分配——大片连续无云区 + 大片连续有云区，二者面积比满足契约。

## 3. 目标架构

### 3.1 分层职责

```
天气系统（CPU，行星尺度，确定性）
  └─> 云场权威：覆盖率体系、锋面/气旋/晴空区、每点 LCL、每点云顶、云种概率
        │  烘焙为多通道纹理 + GPU 可读的结构化数据
        ▼
云体渲染（GPU，WebGPU 原生）
  ├─ 远景（S3/S4）：行星尺度自适应体积 march，逐射线裁剪 + 空域跳过
  ├─ 中景（S2）：云海，同一密度函数，步长细化
  └─ 近景（S1）：逐片云高度差异 + 逐区域云底差异
        │
        ▼
大气（GPU）：独立的散射体，与云共享深度与合成，但不共享 march
        │
        ▼
深度引导上采样；阶段 7 再由统一 TAA/history 系统接管时域
```

### 3.2 关键设计决定（每条都对应上面一个失败或一条要求）

| # | 决定 | 对应 |
|---|---|---|
| D1 | **密度函数唯一。** 远/中/近景、CPU 过场雾、云影、水面反射全部调用同一个 `cloudDensity(worldPos)` 契约。不允许"远景用解析贴图、近景用体积"的双实现。 | C1、旧实现 CPU/GPU 不一致 |
| D2 | **步进预算按被解析对象的尺度分配，不按壳厚度。** 步长由"当前射线段内的云种最小特征尺度"决定，并对每条射线**先求交出实际占用的高度带**再 march。 | 白色色块、忽有忽无 |
| D3 | **空域跳过（empty-space skipping）。** 行星尺度低分辨率占用体（occupancy volume）先粗跳，命中后细化。这是 S3 性能的唯一可行解。 | S3 性能、R1 |
| D4 | **单帧先稳定，时域只有一个所有者。** 阶段 4 禁止帧序抖动，也不把静态屏幕 hash 当默认答案；优先占用段中点/确定性求积并用收敛阶梯消除结构性误差。阶段 7 才由全屏 TAA + 运动向量统一管理几何、着色与体积 history。 | 上一轮 75–138 px 抖动、屏幕相位爬动及阶段 2 运动污染教训 |
| D5 | **云底 = 逐点 LCL（抬升凝结高度），不是全球常数。** 由温度/露点/湿度/地形抬升推出。 | S1(b)、C4 |
| D6 | **单片云的云顶由该点对流能量决定，同种云不同高度。** | S1(a)、C4 |
| D7 | **覆盖率是行星尺度面积契约**，由天气体系分配，不是局部密度目标。 | C5、S3 |
| D8 | **垂直方向：空层压薄，第一层云抬高。** 高度表按真实大气但压缩空档。 | C2、C3 |
| D9 | **绝不回退到 GLSL ShaderMaterial**（AGENTS.md 硬约束）。WebGPU 走 TSL/NodeMaterial；WebGL 仅作回退，且回退可以在质量上妥协。 | R2、AGENTS.md |

### 3.3 云种表（R3：单层内也要多种）

高度按地球实际值，`LCL` = 该点抬升凝结高度（动态，350–4200 m）。**每种云的云底/云顶都带逐点扰动**，禁止同高度（C4）。

**低云族（云底 = LCL，逐点不同）**
| 云种 | 底 | 顶 | 触发条件 | 形态特征 |
|---|---|---|---|---|
| 层云 Stratus | LCL | LCL+600 | 高湿 + 低对流 + 稳定 | 无结构均匀薄幕 |
| 层积云 Stratocumulus | LCL+200 | LCL+2200 | 中湿 + 弱对流 + 海洋 | 规则胞状，有缝隙 |
| 积云 Cumulus humilis | LCL | LCL+1200 | 弱对流 | 扁平小块，间距大 |
| 积云 Cumulus mediocris | LCL | LCL+2500 | 中对流 | 花椰菜状 |
| 积云 Cumulus congestus | LCL | LCL+6000 | 强对流 | 高塔，垂直发展 |
| 积雨云 Cumulonimbus | LCL | 13000 | 极强对流 + 高湿 | 贯穿整层，砧状顶 |
| 雨层云 Nimbostratus | LCL | LCL+4500 | 高湿 + 锋面 | 厚重无形，降水 |

**中云族（4000–7500 m，与 LCL 解耦）**
| 云种 | 底 | 顶 | 触发条件 |
|---|---|---|---|
| 高积云 Altocumulus | 4000±800 | 6500±600 | 中层湿 + 弱不稳定 |
| 高层云 Altostratus | 3500±600 | 6000±800 | 中层湿 + 稳定，锋面前缘 |
| 荚状云 Lenticular | 5000±700 | 6200±400 | 地形驻波（需地形梯度 + 风） |

**高云族（7000–13000 m）**
| 云种 | 底 | 顶 | 触发条件 |
|---|---|---|---|
| 卷云 Cirrus | 8000±1200 | 12000±1000 | 高层湿 + 高空风切变 |
| 卷积云 Cirrocumulus | 9500±800 | 12800±700 | 高层弱对流 |
| 卷层云 Cirrostratus | 7500±900 | 11000±900 | 锋面远前缘，成片 |
| 砧状顶 Anvil | 9000 | 13000 | 由 Cumulonimbus 顶部铺开 |

**特殊**
| 云种 | 高度 | 触发 |
|---|---|---|
| 夜光云 Noctilucent | 76000–85000 | 极高纬 + 夜侧（已有实现可参考其触发条件，但密度函数要接入新契约） |
| 地面雾/辐射雾 | 0–LCL | 夜间辐射冷却 + 高湿 + 低风 + 低洼地形 |

**云底扰动（C4 的实现要求）：** 每种云的 `base` 与 `top` 都要加一个由位置驱动的低频噪声偏移（幅度 ±10–20%），且**同一云种在不同位置的偏移不同**。禁止用全局常数。

> **实现建议（2026-08-09 审查修订）：噪声在 CPU 烘成 3D 纹理，GPU 只做采样，不要 TSL/JS 各写一份噪声函数。** 共享字节只消除了随机源漂移，不能保证坐标变换、插值、云种混合与消光数学一致；阶段 4 仍必须在真实 WebGPU 上做 CPU/GPU 随机点与固定切片误差测试，不能把 fp32 CPU 仿真当作已完成。

3b. `cloud-occupancy.js`：烘一个行星尺度低分辨率 3D 占用体（例如 128×64×32，经纬×高度），每体素记录"该体素内是否可能有云 + 最大密度上界"。用于：
   - 空域跳过：粗步长快速穿过空体素
   - **逐射线高度带裁剪**：先求出这条射线实际穿过的占用高度区间，只在该区间内 march

3c. 步长策略（**替换掉"壳厚度百分比"这个错误**）：
   - 步长 = min(该段内云种的最小特征尺度 / 5, 视角相关上限)
   - 保证**任何视角下，任何云种在其厚度方向上至少 4 个采样**
   - 允许总步数上升，先靠 3b 的空域跳过控制成本；时域摊薄只在阶段 7 的统一 TAA/history 验证后使用

> **两处自相矛盾，实施时按这里的结论走（2026-08-04 评估时发现）：**
> 1. 原文写"最小特征尺度 / 3"，但闸门要求 ≥ 4 个采样 —— 厚度 T 内步长 T/3 只有 3 个采样，**/3 与 ≥4 直接冲突**。T/4 是满足闸门的数学临界值（任意起始相位下最坏情况恰好 4 个），故取 **/5 留一档余量**。
> 2. "最薄云种"两处取值不一致：本节写层云 600 m，阶段 0 实测记录写的是"壳内最薄特征 400 m → 步长下限 100 m"（400 m 是厚度扰动后的实际最薄值）。**以 400 m 为准** —— 闸门要针对云种表里扰动后的真实最小厚度，不是名义厚度，故步长下限 400/5 = **80 m**。

**验证（这是必须做的量化闸门，直接对应上一轮的失败）：**
- 新建 `tools/cloudsamplingtest.js`：对 0°/45°/60°/70°/80°/88° 六个视角，断言**最薄云种内的采样数 ≥ 4**。这张表就是 §1 那张表的修复版，必须逐行通过。
- 断言 CPU 与 GPU 密度一致（C1）

> **注意闸门的约束方向会翻转，别照抄 §1 那张表的直觉。** §1 里 88° 最差（0.2 个采样），是因为旧代码用**固定 48 步预算**摊到整条穿行路径上 —— 视角越掠、路径越长、每步越粗。改成**固定步长**之后关系反过来：穿过 400 m 厚的层云，0°（顶视）光程最短（400 m），是**采样数闸门的临界视角**；88° 光程最长（平板近似约 11 km，球壳正切极限下穿 400 m 壳可达 ~69 km），采样数最富余，但**总步数最多**，成为性能的临界视角。所以 3b 的占用体与空域跳过不是可选优化，而是让掠射视角能跑起来的前提。

**运动走样根治（2026-08-06 用户硬性要求，必须完美解决、不留残留）：**
残余微闪已实锤归因为**无 TAA 的着色走样**（详见 §6）：银河星点走样（WebGPU 点精灵永远 1px 硬方块）+ 地形高频纹理走样。本阶段**必须**落地：
- [ ] **TAA（时域抗走样）**：全屏 TAA，含运动向量、历史拒绝、与体积层累积器的统一历史管理（阶段 2 累积器的重投影修复并入此项——先修重投影，连续大幅运动逐帧验证，再启用）。验收标准：**静止 seamtest 0 px + 连续大幅扫镜逐帧无可见闪烁**，二者缺一不可（静止 0 px 单独不再被接受）。
- [ ] **星点渲染改 instanced billboard**（方案已设计，2026-08-06）：Points → InstancedMesh quad + 圆形软衰减 + 尺寸下限 + 亮度面积守恒。若 TAA 先行且星点在 TAA 下已稳定，此项可降级为可选，但**星点 1px 硬点在 TAA 历史里会产生拖影/拒绝噪声，标准答案仍是 billboard**。
  - **根因**：WebGPU 点精灵永远渲染为 1px 硬方块（`PointUVNode` 官方注释确认："In WebGPU, point primitives always have the size of one pixel"——`gl_PointSize`/sizeNode 在 WGSL 下无效），`makeStarPointsMaterial`/`makeBackdropPointsMaterial` 里的尺寸 clamp 全是空话，转镜时 1px 硬点跨像素边界必闪（实测星带区域走样 ×1486）。
  - **实施（galaxy.js）**：新增 `makeStarQuadsMaterial({ physicalSize })`（TSL `MeshBasicNodeMaterial`）+ `makeStarQuadsGeometry(pos, col, siz, alp)`（`InstancedBufferGeometry`，单位 quad + `aPos/aColor/aSize/aAlpha` instanced attributes，`instanceCount = 星数`），替换 `buildFiniteBackdrop`（银河背景 20000 点，`physicalSize: false`，aSize 直接是像素直径）与 `rebuildNearStars`（真实恒星，`physicalSize: true`，aSize 是物理直径比例 radius/6e6）里的 `THREE.Points`。**WebGL 分支不动**（gl_PointSize 在 WebGL 有效）。
  - **材质要点**：顶点做世界空间 billboard 展开（`centerWorld = modelWorldMatrix × aPos`；`camRight/camUp` 取 `cameraWorldMatrix` 前两列；`sizeWorld = sizePx × dist / uProj`；positionNode 输出对象空间 = `modelWorldMatrixInverse × worldPos`）；像素直径 clamp 下限 2.2px（原 1.8 硬点）；片元圆形软衰减 `smoothstep(1.0, 0.3, r)`（r 来自 quad uv）；**亮度面积守恒** opacity ×= (1.8/sizePx)²（原 1px 硬点能量摊到 2.2px 光斑要降亮度，否则银河带变亮）；恒星的 `discPx = 1.2e7×aSize×uProj/dist` 真实角尺寸语义保留；`uDim` 接口保留（galaxy.js:569-570 在用）。
  - **main.js 配套**：`updateStarProj()`（main.js:595）里给 `backdropMaterial.uniforms.uProj` 也更新（现在只更新 starMaterial）。
  - **验证**：慢扫镜帧序列（0.11°/帧）星带区域 diff 从 ×1486 降到接近视差水平；肉眼连续转镜星带不闪。
- [ ] 地形纹理走样由 TAA 覆盖；若 TAA 后仍有可感知残留，加地形 shader 的屏幕空间频率衰减（fwidth LOD bias）。

> **TAA 的责任边界：** TAA 处理亚像素几何/着色采样的时间走样；它不能修复当前帧系统性漏采、错误消光、错误重投影或低分辨率 silhouette 的偏差。阶段 4/5 的单帧收敛、全分辨率大气边缘和光流补偿运动闸门必须先独立通过，禁止把“以后有 TAA”当作欠采样许可。

- 空域跳过的实际收益测量
- 占用体分辨率调优
- 时域累积的采样摊薄倍率
- 半分辨率 + 深度引导上采样的质量/成本平衡
- 云场生命周期：worker 生成与取消令牌；正常仅一个活动行星、跃迁/门户期间最多两个；CPU/GPU LRU 与显式 dispose；handoff 后 2 帧内释放旧资源；bands/occupancy 双缓冲更新不撕裂。
- 预算基线（2026-08-09 实测）：默认 fields 42,467,328 B（40.50 MiB）+ occupancy 4,227,072 B（4.03 MiB）= 44.53 MiB/行星，冷生成 5.73 s + occupancy 56.9 ms。单行星常态 CPU/GPU 各 ≤ 45 MiB，双行星过渡各 ≤ 90 MiB；生成不得阻塞主线程，上传分帧且单帧额外预算 ≤ 4 ms。
- WebGL 回退路径：允许显著降质，但不允许崩

### 阶段 1 实测记录（2026-08-04）

**产出**：`src/cloud/weather-system.js`（完整实现）、`tools/weathersystemtest.js`（接入 `npm test`，另有 `npm run test:weather-system`）。

**与 `src/weather-field.js` 的边界（阶段 0 遗留的待定项，现在定了）**

旧的 `weather-field.js` **保留**，但**降级为"观察者处的玩法天气"**：降水、能见度、阵风、fixture、world-lock 指纹仍归它。它**不再是云的权威**。理由是它的 `coverage` 通道本质上是"每点的密度目标"——正是 C5 要消灭的那个错误：把密度乘 0.5 得到的是处处半满的花斑，永远得不到大片连续晴空 + 大片连续云系。

新模块因此**从环流结构重新构建云场**，只与 `weather-field.js` 共享三条约定：+Y 转轴、按绝对小时平流（绝不用逐帧增量）、350–4200 m 的 LCL 区间。两者的指纹函数也分开（`weatherSystemFingerprint` vs `weatherFieldFingerprint`），所以本阶段 **world lock 指纹未漂移**（实测仍是 `6aa8d97…`）。

**C5 是怎么被结构性满足的（不是调参）**

做法：把云场建成一个**低频的天气位势**（Hadley/Ferrel 结构 + 蜿蜒的风暴轴 + 离散气旋 + 离散副高 + 地形抬升/背风干化），然后**取阈值**。校准覆盖率时**只动这一个阈值偏置**（`coverageBias`，二分求解）。

关键在于：因为位势是低频的，移动阈值是**让整个天气系统涨落**，而不是让每个像素淡入淡出。实测连通域分析（3000 点等面积格 + 邻接图）：

| 指标 | 实测（5 个 seed） |
|---|---|
| 80% 晴空面积所需连通块数 | 1–2 块（测试闸门 ≤ 6） |
| 最大单块晴空占全球面积 | 25.5%–44.6%（闸门 > 8%） |
| 80% 云区面积所需连通块数 | 1–2 块 |
| 覆盖率契约命中 | 0.2/0.35/0.5/0.65/0.8 × 8 seed 全部在 ±0.05 内，t+720 h 后仍在 ±0.07 |

**"从太空看的遮挡"不等于"有云"**：卷云是半透明的，若把高云也算满覆盖，就能在星球看着很空的情况下"达标"。所以覆盖判据用的是按族光学不透明度合成的遮挡率（低云 1.0 / 中云 0.85 / 高云 0.45），超过 0.5 才算被云遮住。

**测试抓到的真实问题：露点差不能线性映射**

第一版用 `Td = T - (1-humidity)*30`。结果海洋 LCL 平均 1270 m、干燥内陆 2342 m —— **两者只差 1 km，全球云底仍然接近一个平面**，这正是 S1(b) 要消灭的天花板感，而"LCL 随位置变化"这句话在字面上还是成立的（所以只断言"有变化"是不够的，必须断言分离度）。

根因不是常数小了，是**关系式错了**：饱和的海洋空气离露点只差 1–2 K，沙漠空气能差 25 K 以上，这个关系是超线性的。改为 `(1-humidity)^1.45 * 36` 后：海洋 396–414 m、内陆 2471–2606 m（8 个 seed），**差出 2.1 km**，云底真正成为局地空气的属性。

**云种权重：按族内归一，不是全表归一**

低/中/高三层在同一点上是**真实共存**的，全表归一会让它们互相抢份额（有卷云的地方低云就变少）。所以权重在**族内**归一，再乘以该族的面积掩码。另外加了两条物理门：
- 砧状云权重乘以其母体积雨云的权重 —— 无母体不生砧，旧系统会在无对流的静风区长出高空冰盖。
- 某族若没有任何云种的触发条件成立，该族的量**塌缩为 0**，而不是退化成默认铺一层层云。面积掩码说"这里可能有云"，触发条件说"是哪种云"；答案是"都不是"时就该没有云。

**设计要点（与计划的差异都在这里）**

- **累积放在半分辨率、上采样之前。** history 纹素与产生它的采样一一对应；先上采样会把邻居混进 history，让累积器和重建滤波器对"同一个表面"的判断不一致。两者现在共用 `temporal-policy.js` 里的同一组阈值常量。
- **重投影用相机相对坐标。** 绝对世界坐标在 ~1e7 m 落在 fp32 的 [2²³,2²⁴) 区间，ulp = 1 米，直接投影会沿着行星边缘拖出米级 history 涂抹。改为投影"相机相对偏移 + 帧间导航位移"（`p_prev = p_now + (nav_now − nav_prev)`）。
- **重投影面是大气壳球，不是不透明深度缓冲。** 被累积的信号是参与介质，这些纹素大多根本不打到几何体；壳命中给每个天空像素一个稳定且有物理意义的帧间对应关系。
- **`alpha = 1/min(frames, cap)`**，cap 移动时 8、静止时 64 —— 真正的渐进平均，不是永不收敛的指数模糊。静止时 alpha 单调下降，这是 seamtest 0 px 闸门的算术依据。
- **原型假设旋转和 FOV 变化不失效 history。** 单个解析点的矩阵投影能到 1e-6，但这不等于体积信号的对应、遮挡和拒绝都正确；连续 ±27.5° 硬件扫镜已推翻完整实现。阶段 7 必须用 motion vectors/光流真值重新定义，而不是继承这句旧假设。
- **全 tap 被拒时回落到同位纹素，不是 0。** 行星边缘的天空像素四个邻居可能全落在行星上，返回 0 就是"大气一转镜就闪"的那个洞。

**测试抓到的两个真 bug（都是静默失败类）**

1. **位姿latch顺序。** resolve pass 在同一帧内跑在 `policy.update()` **之后**，所以上一帧位姿必须在 `update()` **开头**提升，不能在结尾latch。写成结尾latch的话每帧都重投影到自己的相机 —— 恒等变换、累积实际关闭，但帧计数、alpha、所有失效指标读起来全都完全健康。现在改成 staged-pose 提升，并在测试里加了显式的"非恒等"断言（对 `THREE.PerspectiveCamera` 在上一帧位姿下的真值投影比对，1e-6）。
2. **1/n running mean 对真实内容变化的滞后。** 首次上硬件后 seamtest phase 1 在 factor 2.0（alt 557207 m）报 **10 px**，基线 0 px。排查路径：先怀疑重投影 resample，加了 sub-texel snap —— 无效；再把 history 强制关掉（保留节点在图里）—— 立刻 0 px，证明是 blend 而不是重投影。根因是 `1/n` 均值只以 1/n 的速率遗忘旧内容，n≈20 时地形/天气在 seed 之后继续 settle 的那部分被拖了几十帧。修复：把原本只作用在 alpha 通道的拒绝判据补上**辐亮度 clamp**（`HISTORY_COLOR_REJECT = 0.12`），真实变化的滞后被限制在 1 帧，而远小于该阈值的采样噪声照旧参与平均。

### 8.1 知乎《一个简单的体积云多重散射近似方法》—— 全文要点逐式抄录

- **作者：** 窝的舔　**日期：** 2022-01-16　**原始链接：** https://zhuanlan.zhihu.com/p/457997155
- **作者的动机：** UE4 的 MS 近似效果不好，Horizon 的魔法参数太多。期望：有物理依据、魔法参数少、能看出 dark edge、运算量少。

**n 阶散射的严格式：** 采样点 x₀ 沿 v 出射的 n 阶散射

```
E_n(x₀, v) = ∫_ω L(x₀, w) · P(v, w) dw
L(x₀, w)  = ∫₀^D T(x) · E_{n-1}(x, w) · σ_s dx        （D 为云的边界）
```

**三条（作者自认不科学的）假设：**
1. 所有相位函数近似为各向同性（uniform）；
2. 计算 n 阶散射时，认为其余位置的 n-1 阶散射与当前采样点的 n-1 阶散射完全一致；
3. 认为其余位置的介质特性与当前采样点完全一致。

（作者注：Hillaire20 对大气做同样假设没问题，因为大气是近均匀介质；云的特征频率高得多，偏差肯定大，"但聊胜于无"。）

**化简链：** 假设 1 让 P 提出积分并与球面积分消掉；假设 3 让 σ_s 提出；假设 2 让 E_{n-1} 提出：

```
E_n(x₀) = σ_s · E_{n-1}(x₀) · ∫₀^D T(x) dx
⇒  E_n / E_{n-1} = σ_s ∫₀^D T(x) dx ≡ f_ms
```

**几何级数求和得全部高阶散射：**

```
E₂ + E₃ + … = E₁ · (f_ms + f_ms² + f_ms³ + …) = E₁ · f_ms / (1 − f_ms)
```

**f_ms 的解析解**（因假设介质均匀）：

```
f_ms = (σ_s / σ_e) · (1 − e^{−D·σ_e})
```

其中 **D 是魔数**，物理直觉是"把采样点周围的云视作均匀球体时该球的半径"。D 越大 MS 越亮。**作者效果图取 D = 500 m 常量**；D 可开放为美术参数或动态估算。σ_s/σ_e 用**当前采样点自己**的散射/消光系数。

**shader 里的用法**（左边单次散射，右边 MS 项）：

```
dL(x, camera) = E_sun·T_sun·P(sun, camera) + E_sun·T_sun·(f_ms/(1−f_ms))·P_iso
```

**作者自己指出的核心局限：** f_ms 只依赖采样点自己的 σ，是纯局部量 → 效果"非常锐利"：密度低的点特别暗、密度高的点特别亮。理想效果应是低密度点在周围密度高时也被照亮，整体偏"软"。作者提出的补救是**做一次低 LOD（模糊）密度采样，用模糊后的 σ_s、σ_e 代入公式** —— 但他没有尝试（"感觉改起来会比较麻烦"）。

**参考文献：** [Hillaire20] A Scalable and Production Ready Sky and Atmosphere Rendering Technique。

### 8.2 本地 HanPi/HPVolumeCloud 包 —— phi_fwd 实验候选

- **位置：** `D:\Eray0\Documents\_GitRES\Game\建议参考的优质项目\大气与体积云参考\HPVolumeCloud-main`（仓库外）。核心文件 `VolumetricClouds.hlsl`（~74 KB），推导全文 `Docs/PhiFwd_FromRTE.md`，效果对比图在 `compare/`。
- **许可/来源边界：** 目录含 MIT LICENSE，但没有可核验的仓库历史/远端；因此许可允许阅读复用，不等于公式已经同行评审、成熟生产验证或只需 HLSL→TSL。形态项逐项 A/B，光照必须重做量纲/能量/参考积分验证。

**它试图解决什么：** 单次散射会让厚云内部、云底和侧面过暗；高阶散射会逐渐去方向化。包内 phi_fwd 试图补一个加性漫射项，但“加性独立”并不自动意味着可与另一套多重散射近似无重复地叠加。

**包内声称的推导链（细节回 `Docs/PhiFwd_FromRTE.md` 查，以下不视为已验证结论）：**

```
RTE → 扩散近似（τ≫1，g_eff→0）→ Helmholtz 型 → 格林函数 G(x,x') = e^{−κr}/(4πr)
    → 有效源 Q_eff（慢衰减 + 局部散射沉积 + 边界置信度）→ 沿太阳方向 1D 离散 → phi_fwd
```

**候选结论与常数（只能用于实验起点）：**
1. g=0 时 `κ = σ_t·√(3(1−ω₀))`。**ω₀ = 0.999 ⇒ ODScale = κ/σ_t ≈ √0.003 ≈ 0.055** —— 漫射场衰减比 Beer–Lambert 慢 ~18 倍，这就是"云芯 τ=20 仍留 ~33% 漫射能量、内部不越走越黑"的物理原因。
2. 源项四因子：`Q_eff = T_abs · σ_sΔs · σ_tr · C_iso`。T_abs = exp(−(1−ω₀)·OD) 是"无逃逸漫射源的吸收存活率"（不是单次透射率！用 e^{−τ} 会让云内过暗）；C_iso = 1−exp(−τ_iso) 是各向同性建立权重，τ_iso ≈ (1−g)·τ —— **刚入云时方向记忆仍强，不能立刻当各向同性源**。
3. 边界项折成置信度 `B_eff = C_top · C_bottom`：C_top 用 2D 云顶高度代理差分出边界法线，对太阳方向做 wrap 光照（**避免背光侧被错误打亮**）；C_bottom = 1−exp(−h_local/H_soft·p)，H_soft 随云柱厚度放大 1→4 倍（厚云底部更难从下方获得注入）。
4. **薄边缘门控：** 扩散近似只在 τ≫1 成立。低密度薄雾区必须密度门控，否则边缘会错误地贡献完整各向同性散射。README 特别强调：**现实中稀薄云接近灰黑色（各向异性主导），只有云团内部才是同性漫射的亮** —— 这正是"稀薄边缘该灰不该白"的依据。
5. 自阴影锥形光 march 的工程参数：几何级数步长（相邻步比率 2.0，首步 ≥ 5 m，总覆盖 ≤ 6000 m —— 再远密度≈0 纯属浪费），逐步 mip 偏移 `j/(N−1)·3`；反解首步宽度使 N 步正好覆盖总距离，**加步数 = 加近处精度而非加覆盖**。
6. 高空薄云单独一条光照路径（均匀步进、不采 3D 噪声、光程限 3 km）—— 薄层不值得锥形采样。
7. 包内实现选择方向性散射不施加 powder，并使用多八度 `attFactor/conFactor`；这属于实现选择，不是来自 Hillaire 2020 大气论文的已证公式。

### 8.3 知乎闭式解的数值陷阱（直接照抄会炸，实现前必读）

`f_ms = (σ_s/σ_e)(1−e^{−Dσ_e})` 在 OD = D·σ_e ≫ 1 时 → ω₀。云的 ω₀ ≈ 0.999，于是乘子

```
f_ms/(1−f_ms) → 0.999/0.001 ≈ 1000×
```

按我们的候选尺度，乘子可能逼近约 1000 倍并炸白。简单 clamp 或篡改反照率只能让数值不炸，不能恢复物理正确性；因此该闭式解不进入生产实施路径，只保留作反例。
