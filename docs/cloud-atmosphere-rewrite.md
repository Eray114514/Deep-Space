## 1. 验收目标

| 编号 | 不缩减的要求 |
|---|---|
| R0 | 绝对写实风格；云与大气达到用户目标图所表达的形态、光照、层次与尺度 |
| R1 | 画质优先，同时优化性能；不能以关闭体积、抹细节或无限降分辨率换取完成 |
| R2 | 发挥 WebGL2/GLSL 能力；原 WebGPU 专属要求已撤销 |
| R3 | 多云种，且同一高度族内也要可辨识，不能用多个名字包装同一层膜 |
| R4 | 原清单是下限，可以扩展；扩展必须形成可验证的玩家收益 |
| R5 | 大气不能退回经验蓝壳；云保留成熟观感，具体实现可按证据替换 |

| 场景 | 必须看到的结果 |
|---|---|
| S1 地面仰视 | 每片云高度/厚度有变化，区域云底受天气和地形影响；不是头顶等高天花板 |
| S2 穿云及云海 | 从云下、云内到云上连续，消光、明暗、能见度和侧切面有可信体积 |
| S3 低轨斜视 | 成体系云区与大片晴空、细节/自阴影/薄大气临边，不能是白色贴片；广视野成本受控 |
| S4 整球 | 整体云量、天气系统与行星尺度可读，昼夜/晨昏关系自然 |

| 契约 | 验收语义 |
|---|---|
| C1 | 固定行星、世界位置和时间，云的存在/高度/光学属性不随相机改变；太空晴空方向抵达后仍晴空。正常运行再验证风平流与时间演变 |
| C2 | 上升不能长时间毫无环境变化；用正常飞行耗时、云/天空/地平线变化联合评价，不用“每 1 km 必须变色”强迫压扁大气或虚构云 |
| C3 | 地面到首层云有探索余量；考虑局地地形与天气，不能为避开最高山把整球云底抬高 |
| C4 | 同种云也有不同云底、厚度、云顶与侧切面；不是全局统一噪声偏移 |
| C5 | 云量是整体云遮挡面积，不是各地都保持相同局部密度；有云区内部仍有自然空隙 |

云种范围继承原要求：低云为层云、层积云、淡积云、中积云、浓积云、积雨云、雨层云；中云为高积云、高层云、荚状云；高云为卷云、卷积云、卷层云、砧状顶；特殊为雾和夜光云。现有 `cloud-species.js` 的 16 项为数据基础，壳内 14 项不等于画面已实现 14 种。雾、夜光云有独立高度和光学条件，不强塞进主云壳，也不能用发光整球代替夜光云。

高度表是模型输入而非固定外观：地球型天气可用 LCL/对流层顶作校准起点；异星需显式配置，禁止按行星半径机械拉伸全部光学尺度。世界高度、离局地地表高度和归一化云内高度分别命名。云底整体位移与厚度变化分开，允许高山穿云。

## 3. 生产职责与不变量

1. **一个天气权威。** 目标由 `weather-system.js` 或其必要演进提供稳定世界坐标/绝对时间状态。生产云、解析远云、云影、反射、雨雪雷雾、风和玩法能见度从同一状态派生。允许分辨率和表现不同，不允许各算一份覆盖率。迁移接口先闭环一个天气场，再扩云种。
2. **密度独立于观察者。** `density(position,time)`、云种高度和消光系数不读取相机位置。质量档只改采样/重建策略；LOD 保持占用、柱光学厚度和主要轮廓。不能以改变密度几何代替 LOD。
3. **光学单位与曝光分离。** 消光按每米/每公里统一换算；散射反照率与相函数有明确含义。双星逐星照明，全食归零直射，环境/多次散射单算；不能给直射硬留 35% 再称物理日食。艺术控制须显式标注、限定范围并做多条件 A/B。
4. **共享深度，不混淆介质顺序。** 保留独立全分辨率大气与云 march，但明确每段路径的散射 `L` 与透射 `T`、RGB 透射与标量 alpha 的差别。云前空气、云内介质、云后空气都要正确处理；“先把完整大气画到背景，再把云贴上去”不能作最终模型。前景、停泊舱、透明水面/玻璃、远端/门户都要有显式接收与遮挡边界。
5. **同一位置的照明有同源输入。** 地面、水面、云和大气共享逐星辐射与遮挡几何；共享 `sunDir` 不等于共享天空辐照/空气透射。R 只做曝光/显示，不替介质修颜色。
6. **单帧先收敛，时域统一治理。** 新效果不另建 history；现存云 jitter/history 在过渡期成套保护。统一 TAA 可管理不同信号的历史与拒绝规则，不意味着把所有深度压成一张表面深度，也不要求粗暴把不同介质合成一张历史。

### B7：统一 TAA、性能与生命周期

2026-10-20 基础任务接入了共同 `RenderFrameState`：前后帧相机/双精度原点/行星刚体、成功整帧提交、sequence/时间 epoch/内容/布局失效，以及空气/云/云影实际眼点。修复主循环强制使 history 有效和私有预热失效调用为空的漏洞，云已有刚体映射；[帧接口固定证据](baselines/foundation-frame-state-2026-10-20/README.md)保留原检查。续轮增加逐 tap 不透明深度支持、天空分类、未知深度拒绝、当前邻域 signed RGBA 限幅，以及严格静止的原 texel 路径，见[接口 v1.3](medium-render-contract.md)与[过滤固定证据](baselines/foundation-history-filter-2026-10-20/README.md)。这是现有局部 history 的质量约束；云占用深度/天气平流、逐物体 motion、共同 jitter、完整反遮挡和统一 TAA 仍未实现，下列整项不勾选。不同云层平流速度及天气场变形不能用一个全局风旋转冒充正确对应。默认长冷暂停及画质否决继续保留，这不是云专项恢复或性能完成。

- [ ] 全屏 TAA 含相机与物体运动、深度/遮挡拒绝、云平流补偿、历史限幅；吸收或替换现有局部 history。相机跳转、天气突变、切星、resize、context restore 可靠失效。
- [ ] 静止冻结的确定性/噪声收敛与连续大幅扫镜都通过；运动比较使用已知变换或可信重投影补偿，另查反遮挡、拖影、模糊。不能用同姿态回访相同推导转镜不闪，也不对正在改变的天气强求 0 px。
- [ ] 星点/地形/云分别隔离归因，TAA 不能掩盖单帧漏采。必要时补解析覆盖、纹理过滤、频率衰减。
- [ ] orbit/approach/surface 三场景、三档记录整帧 p95、1% low、GPU 成本和质量；Ultra 沿用总路线图 2K 硬件门槛。其他硬件/档位先登记预算，不能拿不同 GPU 数字互相替代。
- [ ] 如接云场纹理：worker 生成/可取消、分帧上传、时间戳原子交换、切星释放与 context lost/restored 在**真实 WebGL2** 验证。旧 WebGPU 的 44.53 MiB CPU / 44.50 MiB GPU 仅是旧场尺寸，不能当当前资源预算已达标。
- [ ] 基准资源预算：常态单活动云场 CPU/GPU 各 ≤45 MiB，双场过渡各 ≤90 MiB，上传单帧额外 ≤4 ms，handoff 后两帧释放旧场；如更优方案需改预算，写实测理由。重复切星/门户/恢复测试应到平台值，覆盖大气 LUT 缓存，不能只测云管理器。

## 5. 验证证据和参考

基础闸门：`test:stage-b` 含参考气柱/LUT/缓存测试；`test:stage-b:gpu` 执行生产 GLSL 读回；`test:stage-b:player` 保留正常 post/HUD 四机位截图与成本观察。B5 另以 `test:b5` 和 `test:b5:player` 覆盖最终传输/照明及玩家链。原有云种/天气/采样/资源、`test:cloud-reference`、大气 visual/motion/traversal、日食、seam 和 performance 工具继续使用。**通过只代表实际断言**；B6 跨消费者、B7 光流/统一 TAA 仍须补齐。

每次勾选绑定源码摘要、可复现状态、原图/连续帧、实际断言与限制；旧报告只作历史基线。自动阈值要能抓住已知坏例，且确认目标确实被渲染；全零差分可能只是效果没有开启。

主要参考：[Hillaire 2020 原论文](https://sebh.github.io/publications/egsr2020.pdf)与 [Bruneton 的实现及参考验证](https://ebruneton.github.io/precomputed_atmospheric_scattering/)。前者提供实时天空/空气透视方法，后者公开量纲、函数及 CPU 参考图验证方法；二者都不是当前实现已经符合的证明。HPVolumeCloud 本地包只作候选形态/算法来源，采用前检查具体版本与许可。删除旧文中二手推导的长篇抄录和“参数直接照用”要求，防止未经参考验证的散射补光成为默认生产方案。

新增主要工程参考为 three-geospatial 的固定版本 WebGL 云/大气/重建设计，以及用户本地 Aether demo 的云形与连续升降；HPVolumeCloud 用于分云种形态候选。完整目录、历史使用证据、源码版本、许可边界与采用优先级集中维护于[参考审查](reviews/cloud-visual-rework-2026-09-30.md)，后续记录实际采用/放弃及 A/B 结果，不再只列项目名。参考整库不等于引入整库，也不改变 WebGL2 决策。
